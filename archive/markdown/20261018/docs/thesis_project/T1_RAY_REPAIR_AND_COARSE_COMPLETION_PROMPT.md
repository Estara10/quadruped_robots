## 4. 射线读取的最小修复要求

优先复用/抽取实际生产读取路径，避免只测一套与生产无关的新实现。

- 使用有明确总耗时上限、尝试次数上限的快照读取策略，允许短暂写入完成后重新取得一致快照。根据现有线程和约5ms控制/20ms策略周期预算选一个小的固定上限，并在执行报告说明依据；不能无限忙等、无界sleep或拖到数据过期。
- 区分 sequence=0（未武装）、奇数（写入中）、前后sequence不一致、有效稳定帧及持续失败。短暂冲突可在预算内重读，持续异常仍触发原安全故障路径。
- 只接受前后sequence一致、非零且为偶数的完整帧。不得接受半写数据。
- 取得一致帧后再取单调校验时间，同一时间用于未来时间戳和年龄判断。
- 原 magic/version、11维、有限值、非零时间戳、真正未来和过期拒绝条件保留；真实无效帧不能靠重试掩盖为有效。
- 不返回上周期缓存并把时间改成当前，不用常量最大距离替代故障。
- 增补最小故障信息：失败类别、首末sequence、尝试次数、读取耗时、已取得的帧时间戳和校验时间；没有取得的字段标明未取得，不以0暗示测到了0。
- 避免每周期大量日志；仅异常、首次恢复或低频汇总记录必要统计，以便观察读取开销与实际policy频率。

必要时修正 publisher 的发布顺序，但不改变射线数值算法或协议语义。先用直接证据判断是否必要，不为此重构整套共享内存。

## 5. 安全中止事件与边界

故障可能发生在新策略帧生成之前，因此不能要求凭空造出一个完整终止策略帧。

- 保存controller实际故障检测单调时间、来源/session、原因及PASSIVE确认时间。
- 把最后有效策略帧作为“最后有效观测”引用；只有实际存在的同周期帧才能标为准确终止帧。
- 无法取得准确物理终止边界时，记录可证明的时间区间或UNKNOWN，不将上一个策略帧硬充故障发生帧，不插值成精确时刻。
- 安全中止、正常运动终局、站立观察和进程清理继续分开。能分析的完整前缀可单独呈现，但不据此前缀声称整个任务无碰撞/未跌倒。
- 错误信息和台账要让下一次故障能够定位，不能只留下通用 `SYSTEM_SAFETY_ABORT`。

本轮不建设命令消费ack、全物理步录制或通用安全系统。

## 6. 最小充分离线验证与构建
