# 双阈值退出参数选取：实验历史、评分与咨询问题

> 整理日期：2026-10-18。本文用于向其他研究者或网页版助手咨询方法，不是最终论文结论。数据摘自既有实验报告和汇总，未新增实验或重新计算评分。

## 1. 研究背景

我正在做本科毕业设计，研究四足机器人在静态障碍环境中，利用风险评价值RA在Agile与Recovery之间切换的方法。RA不是经过概率校准的碰撞概率。

进入阈值固定为E=−0.05，B组采用双阈值滞回：

- RA≥E时进入Recovery。
- RA<X时退出Recovery、返回Agile。
- RA等于退出阈值X时保持Recovery。
- B组无最小保持时间。A组是单阈值参考，进入RA≥E、退出RA<E。

希望综合改善任务到达能力、碰撞表现、到达效率和策略切换稳定性。后续还需进行最小保持时间及A/B/C/D机制对照，因此当前目标是选择有依据的代表性退出阈值，不要求证明全局唯一最优值。

## 2. 共用实验条件与边界

- 平台：Go2、MuJoCo、ROS 2，固定部署策略；策略/RA约50 Hz。
- 目标为(7.5,0)，到达半径0.5 m；任务上限20仿真秒，另设120秒墙钟保护。
- 到达后站立观察5仿真秒；站立与进程清理不计入运动任务指标。
- M1是冻结地图库，开发30张、留出30张；M2是额外制作的6张开发挑战图，不是独立最终测试集。
- 以下三个批次均为开发参数预实验，留出集没有运行策略；没有把跨批数据直接混成同一统计分母。
- 非足端障碍碰撞会终止；足端轻触/撞击单独记录、不直接终止。“非碰撞”不等于没有任何接触或冲击。
- 跌倒、足端撞击、越界、安全中止与站立收尾另行报告。有效记录VALID不等于已证明安全成功；UNKNOWN不当作False。
- 同地图重复运行不代表确定性重放，实测初态可能不同；并非严格相同q/dq和姿态的配对。

## 3. 当前综合评分方案

这是项目自定的工程辅助评分，并非ABS原作者的指标权重。**第一轮400次完成并看到结果后才确定评分；第二轮与第三轮沿用并在运行前固定。**

每条有效任务运行先计算四个0～1的分项：

### 到达项a，权重40%

ARRIVED取1，其他合法任务终局取0。基础设施启动失败/无有效任务不作为普通导航失败补零。

### 非碰撞项s，权重30%

任务窗口的非足端障碍碰撞判定False取1、True取0，UNKNOWN不补成0或1。这是特定碰撞口径，不能称为完整整机安全项。

### 效率项e，权重20%

到达时：e=max(0,1−T/20)，T为到达任务耗时，单位仿真秒；未到达的合法任务终局取0。

### 稳定性项q，权重10%

q=1/(1+f/257.8)。f为0.5秒窗口内短时间反向切换次数，除以有效任务分钟数。257.8是第一轮中A参考的既定统计常数，后续不重新拟合。统计覆盖不足时该项UNKNOWN。

### 总分与聚合

S=40a+30s+20e+10q，满分100。先逐run非线性变换，再对同地图同阈值重复取平均，最后对地图等权平均；不能先平均f再套非线性公式。必要分项缺失时总分UNKNOWN，不重新分配权重。

已知问题：到达项与效率项都奖励完成任务；非碰撞但超时仍得到非碰撞分；跌倒没有独立进入公式。因此评分必须与原始终局、安全字段、Recovery占用一起看，不能只按分数决定安全准入。

## 4. 第一轮：400次宽范围开发比较

### 4.1 设计

- M1开发图10张：dev01、03、05、09、11、15、17、23、27、29。
- 8档X：−0.05、−0.07、−0.09、−0.11、−0.13、−0.15、−0.17、−0.19。
- 每图每档5次，共400条有效任务记录，每档50次。
- X=−0.05实际运行A组单阈值参考；其余为B组，无保持。
- 总终局328到达、50碰撞、21仿真限时、1跌倒。另一次运行前解析失败单独保留，不进入400条分母。

第一轮之后，用户决定把后续探索范围缩至−0.05至−0.13。这是开发决策，不是由统计证明该范围之外全部较差；旧全范围数据保留。

## 6. 第三轮：−0.07与−0.12，36图逐地图比较

### 6.1 设计

- M1开发30图＋M2开发6图，共36图。
- 只比较B组X=−0.07、−0.12，每图每档2次，共144条有效任务结果，每档72条。
- 地图块内两档相邻，第二次重复反转先后；首轮先后平衡，调度种子2026101604。
- 144条全部新运行，前两轮数据不充抵重复。另有1条操作中断INVALID保留，共145次场景启动。
- 固定评分、地图和任务条件；不使用留出集，没有A参考。

### 6.4 运行阶段差异

- 第1–4项：可视MuJoCo GLFW。
- 第5–10项：隐藏MuJoCo窗口，但ROS仍启动RViz。
- 第11–144项：隐藏MuJoCo且关闭RViz；仍依赖DISPLAY/OpenGL，不是真正无显示依赖headless。
- 排除最早4条后，完整配对地图减少至33张，分差约+1.1667；只看第11–144项，完整配对地图31张，分差约+1.1769。
- 上述子集同时改变显示阶段和地图组成，不能把分差反转直接归因为窗口/RViz。缺重复的子集不能冒充完整36图实验。

## 7. 目前面临的选择

第一轮−0.07分数最高；第二轮−0.12分数最高；第三轮总体任务计数略偏−0.07，短反向频率偏−0.12，但共同地图分差区间包含0，运行阶段敏感性也未支持稳定排序。

希望选择一个代表性退出阈值用于后续机制比较，避免无限扩大调参。不能将三轮开发成绩直接拼成独立验证；第三轮覆盖了前两轮地图，M2也参与了候选选择。

## 8. 请重点评估的问题

1. 当前40%到达、30%非碰撞、20%效率、10%稳定性是否适合本课题？到达与效率重复奖励、非碰撞超时仍得30分、跌倒未入公式等问题如何处理？
2. 是否应安全约束优先，再以任务表现和切换质量辅助选择？如需设门槛，应如何避免看过结果后迎合某一候选？
3. 应如何解释三轮分数排序变化，以及第三轮“更多地图支持−0.12，但总体均分略偏−0.07”？
4. 现有证据是否足以选一个可解释的代表性参数，而非宣称显著优越或全局最优？哪些表述适合本科论文？
5. 如需最小补充验证，应怎样控制规模、统一运行环境并保留真正独立的验证？不要建议为了赢得排名不断重跑开发集或筛掉困难图。
6. 如何处理一张地图的评分缺失？共同地图分析之外，是否应做缺失分数范围/敏感性分析，而不是补零或当作安全？
7. 若改评分，请区分现有数据上的探索性重分析与下一阶段预先固定规则；不要通过事后调权直接宣布一档获胜。
8. 如果后续重点是A/B/C/D机制对照，何时应结束退出阈值搜索，转向保持时间与机制效果验证？

请依据实际数据和有限重复次数回答，不预设−0.07或−0.12必然更好，也不要把没有显著差异解释成两者已证实等效。
