# 毕业设计执行路线（FROZEN REBASELINE SNAPSHOT）

> 本文件是 2026-10-06 第一版路线快照，现已冻结。当前轻量路线为 `thesis_project/ROADMAP.md`，不再从本文件产生任务或 Gate。

> 路线按技术依赖和论文证据组织，不沿用旧 Phase/P1 顺序。时间安排紧凑推进，但任何安全或数据有效性前置项不得跳过。

## 总路径

治理基线 → A/B/C/D 合同 → 运行时与终局可观测性 → 四机制实现与验证 → 场景/参数预实验 → 正式配对仿真 → 统计与论文图表 → 实机安全准入 → 低速代表性实机验证 → 论文证据包。

## G0 治理基线更新（COMPLETE，2026-10-06）

- 目标：让开题报告成为最高规划依据，区分 FACT/PLANNED/UNKNOWN/LEGACY。
- 产物：总览、治理、当前状态、路线、Gap、实验计划和新任务合同。
- 通过：顶层文档无旧 Phase 自动执行入口，Active Task 唯一且可执行。已通过文档交叉检查与本地链接检查。
- 禁止：通过前不得继续旧 P1-10、正式实验、训练或实机 RL。

## R1 切换研究合同与原始基线

- 目标：把研究变量从 legacy 实现中分离，形成 A/B/C/D 唯一语义。
- 必须能力：四组真值表、时间基准、参数 schema、模式 ID、事件定义、A 组运行消费证据。
- 验证：受控 RA 序列离线测试 + 一次非正式 runtime smoke，证明配置被控制器消费。
- 证据：合同、测试输出、配置快照、运行帧时间线。
- 通过：边界值、抖动、进入/退出、保持和 NaN/Inf 行为均明确；保持时长不依赖错误频率假设。
- 未通过禁止：B/C/D 实验、场景参数调优、正式批次。

## R2 实验可观测性与终局闭环

- 目标：保证论文每个核心指标都有权威数据来源。
- 必须能力：同钟域 RA/模式/动作生效事件；到达、碰撞、跌倒、超时；数据完整性检查。
- 验证：构造每种终局和切换事件，检查原始帧、事件、终局与派生值一致。
- 证据：字段映射、测试 fixture、有效/失效样例、完整运行包。
- 通过：任何来源缺失或矛盾时 fail closed；单次运行可自动生成完整指标输入。
- 未通过禁止：正式参数比较和安全结论。

## R3 四机制实现与集成验证

- 目标：在同一状态机接口中独立实现 A、B、C、D。
- 必须能力：组别只改变滞回/保持两个因素；参数显式；legacy 模式有迁移说明。
- 验证：四组全边界真值表、配置负例、runtime smoke、回放指标一致性。
- 证据：代码测试、配置、日志和审查记录。
- 通过：B−A、C−A、D−B、D−C 的差异与合同完全一致。
- 未通过禁止：把 `stabilized_switch` 标签当作 D 结果或开始参数优劣比较。

## R4 场景与预实验设计

- 目标：把稀疏/中等/密集障碍转成有区分度、可重复的正式场景，并冻结正式参数。
- 必须能力：冻结几何/目标/初态/种子/碰撞集合；确认基本可达；用已验收的四机制确定参数候选、短时窗口、重复次数和排除规则。
- 验证：各场景小规模预实验，覆盖风险触发和至少一种典型失败；不与正式统计混用。
- 证据：场景清单与哈希、预实验记录、参数选择说明、正式实验预注册。
- 通过：正式变量和统计规则在看正式结果前冻结。
- 未通过禁止：正式 A/B/C/D 批次。

R2 与 R3 的非重叠实现可在 R1 合同冻结后并行；R4 必须等待四机制和核心观测字段可运行，但场景文档化可提前准备。

## R5 正式 A/B/C/D 配对仿真

- 目标：获得可用于毕业论文的核心对照数据。
- 必须能力：三档场景、固定样本、四组配对、完整终局与运行数据。
- 验证：先做批次完整性检查，再计算切换稳定性、安全响应和任务表现。
- 证据：预注册、run manifests、原始记录、排除日志、汇总表、图表生成脚本。
- 通过：所有预定有效样本完成，缺失/异常透明报告，可重算主要表格和图。
- 未通过禁止：选择性补跑后混入原批次、宣称机制优越、进入实机。

## R6 分析、参数讨论与论文图表

- 目标：从数据回答四个研究问题，而非只展示成功案例。
- 必须能力：分场景和总体配对比较、离散程度/区间、失败类型、时间线案例、参数敏感性。
- 验证：结论可由原始数据重算；稳定性改善不牺牲安全/任务性能。
- 证据：冻结数据集、表格、图、分析说明和结论边界。
- 通过：论文“方法—实验设计—结果—讨论”链完整。
- 未通过禁止：依据视觉印象或单一指标下结论。

## R7 实机安全准入

- 目标：证明低速代表性验证可在受控风险下进行。
- 必须能力：站立复验、映射、感知时效、模式切换、速度限制、硬急停、通信异常、物理保护和人员分工。
- 验证：先无 RL，再低风险单模块，最后 dry-run；每项有明确 PASS/NO-GO。
- 证据：检查表、日志、视频索引、配置与负责人确认。
- 通过：所有强制安全项 PASS；任何 UNKNOWN 均维持 NO-GO。
- 未通过禁止：RL 行走、障碍接近和密集场景。

## R8 代表性低速实机验证

- 目标：验证核心机制在现实传感与控制延迟下仍能工作。
- 必须能力：选定有理由的代表组别/场景，低速、静态、可人工中止，保存同构证据。
- 验证：从稀疏到中等，只有安全余量充分时再选密集案例。
- 证据：运行包、视频索引、事件时间线、结果和仿真差异分析。
- 通过：能支持“可部署性与局限”结论；不要求复现极限性能。

## R9 论文证据包与归档

- 目标：让论文中的每个方法和结果都能追溯到版本化证据。
- 产物：最终数据清单、图表、配置/模型/场景哈希、失败记录、复现实验说明、论文实验章节素材。
- 通过：第三方能回答做了什么、为何这样做、数据来自哪里、结论边界是什么。

## 优先级裁剪

- 必做项优先于增强项，增强项优先于可选项。
- 重新训练、动态障碍、极限速度、通用平台扩展只有在 R5 核心证据不受影响时才允许进入。
- 若时间受限，先减少增强项和场景扩展，不削弱 A/B/C/D 因果设计、终局权威或实机安全。
