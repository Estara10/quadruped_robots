# 实验计划

## 1. 实验目标

比较 A/B/C/D 四种策略切换方式在复杂静态障碍环境中的：

- 切换稳定性；
- 风险出现后的响应；
- 避障与任务完成能力；
- 时间和速度代价。

## 2. 场景

- 稀疏障碍：验证基本触发、Recovery 和返回 Agile；
- 中等障碍：观察连续风险和边界附近切换；
- 密集障碍：观察安全、超时和 Recovery 占用的权衡。

现有 PPT 和历史场景只是候选。S6 通过小规模预实验选择最终场景，不额外建设庞大的场景治理系统。

## 3. 核心指标

### 切换稳定性

- 总切换次数；
- 短时间内反向切换次数；
- 相邻切换间隔；
- Recovery 单次持续时间和总占比。

### 安全响应

- RA 满足进入条件到 Recovery 模式的延迟；
- Recovery 动作实际生效延迟；
- 碰撞、跌倒和人工/系统安全中止。

### 任务表现

- 成功、碰撞、跌倒、超时；
- 到达时间；
- 平均速度和必要峰值速度。

切换次数减少但碰撞、延迟或超时恶化时，不能认定为改进。

## 4. 预实验

预实验用于：

- 确认四组实现和指标可用；
- 选择阈值差、保持时间和短时窗口；
- 确认场景可达且具有区分度；
- 确定正式重复次数、超时和无效 run 规则。

参数选择以足够解释研究问题为目标，不进行无意义的穷举网格。预实验不并入正式统计。

## 5. 正式仿真

- 对同一场景、初始条件和种子分别运行 A/B/C/D；
- 固定模型、观测、控制频率、目标和终止规则；
- 每组完成预先约定的重复次数；
- 保存足够计算核心指标的原始时间序列和运行结果；
- 明确记录失败、异常和被排除的 run；
- 正式批次开始时记录 Git commit、模型版本和主要配置；只对关键模型按需记录 hash。

## 6. 单次正式 run 的最小记录

- 组别与切换参数；
- 场景、初始条件/种子和目标；
- 实际 policy 频率；
- RA、模式、位姿、速度、动作和关键障碍输入时间序列；
- 切换、碰撞、跌倒、到达、超时或安全中止；
- 最终结果与耗时。

不要求为每个文件建立 manifest，也不要求复杂 artifact 链。

## 7. 进入正式仿真的条件

- 四组进入、退出和保持行为经过最小功能验证；
- 关键 observation/action 接口与频率正确；
- 核心指标能够从一次试运行中算出；
- 场景、参数、重复次数和排除规则已在正式数据产生前确定。

## 8. 实机验证

实机只做代表性、低速、静态、人工监控的验证。开始前必须确认站立与映射、急停、速度/动作限制、异常停止和真实障碍输入。

实机不要求复制全部 A/B/C/D 仿真矩阵。选择最有解释价值的基线和改进方案，验证实际延迟、切换和避障表现即可。任何明显人身或设备风险未解决时保持 NO-GO。
