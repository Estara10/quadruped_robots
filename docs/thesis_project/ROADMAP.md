# 毕业设计路线图

## 总路径

研究合同与基础闭环 → A 基线 → B 滞回 → C 最小保持 → D 组合 → 场景与参数预实验 → 正式配对仿真 → 结果分析 → 实机准备 → 代表性实机验证 → 论文资产整理。

## S0 项目重新基线（COMPLETE）

目标：从开题报告出发建立独立、轻量的新项目路线。

完成条件：

- 明确研究目标、A/B/C/D 和论文所需结果；
- 识别可复用资产与当前缺口；
- 建立新的 Overview、Roadmap、Current State、Experiment Plan 和当前任务。

## S1 研究合同与基础仿真闭环

目标：确认研究所依赖的关键接口和时间语义，得到可重复运行的基础仿真。

最小验收：

- observation/action、joint/action order、单位和模型输入输出一致；
- 实际 policy/RA 频率可测，hold 时间单位明确；
- A/B/C/D 状态机合同与配置字段冻结；
- 基础场景中 Agile、RA、Recovery 和指标记录链能够工作。

## S2 A 组原始单阈值基线

目标：建立原始切换行为和问题基线。

最小验收：

- 单阈值进入/退出和边界值行为正确；
- 运行时能证明 A 配置被实际使用；
- 至少在代表场景中记录 RA、模式、动作和短时反向切换现象。

## S3 B 组双阈值滞回

目标：只增加滞回，检验其独立作用。

最小验收：

- 进入和退出阈值分别生效；
- B 与 A 除滞回外无有意差异；
- 边界附近切换减少且未明显破坏任务。

## S4 C 组 Recovery 最小保持

目标：只增加 Recovery 侧保持时间，检验其独立作用。

最小验收：

- 进入 Recovery 后实际保持时间符合设定；
- 到期后能够按单阈值条件退出；
- C 与 A 除保持机制外无有意差异，且无明显异常。

## S5 D 组组合机制

目标：组合已经验证的滞回和保持机制。

最小验收：

- D 同时满足 B 的滞回和 C 的保持语义；
- 不引入第三个未声明研究变量；
- 在代表场景中能完成一次稳定闭环运行。

## S6 场景与参数预实验

目标：确定正式实验的场景、参数和统计规则。

最小验收：

- 稀疏、中等、密集场景基本可达且有区分度；
- 选择进入/退出阈值、保持时长、短时窗口和超时；
- 冻结重复次数、种子/初态策略和无效 run 规则；
- 预实验数据不混入正式结果。

## S7 正式 A/B/C/D 仿真实验

目标：获得毕业论文核心对照数据。

最小验收：

- 四组在相同实验条件下完成足够数量的配对 run；
- 能计算预先定义的全部核心指标；
- 异常和失败 run 有明确记录，不选择性隐藏；
- 记录正式使用的代码版本、模型和主要配置；必要时对关键模型记录 hash。

## S8 结果分析与论文图表

目标：回答四个研究问题并解释机制与局限。

最小验收：

- 给出 B−A、C−A、D−B、D−C 比较；
- 同时分析切换稳定性、安全和任务表现；
- 包含典型时间线、失败案例、统计表和论文图；
- 所有结论都能追溯到正式数据。

## S9 低速实机准备

目标：确认实机测试不会造成明显人员或设备风险。

最小验收：

- 站立、关节/电机映射和通信稳定；
- 急停、速度/动作限制、异常停止和人工监控可用；
- 实机障碍输入及 RA/切换链可观测；
- 未通过时保持 NO-GO。

## S10 代表性低速实机验证

目标：验证核心机制在现实传感和控制延迟下仍可工作。

最小验收：

- 从受控稀疏静态场景开始；
- 选择有明确理由的代表组别，不要求复现全部仿真参数扫描；
- 保存视频、关键时序、终局和异常记录；
- 给出与仿真差异及局限分析。

## S11 论文实验资产整理

目标：形成可直接用于论文与答辩的完整材料。

完成条件：

- 数据、表格、图、视频索引、配置和结论边界整理完成；
- 方法、实验设置、结果和讨论能够互相对应；
- 可说明正式实验使用的代码、模型和配置版本。

## 依赖原则

- 任一时刻只有一个主要 Active Task；
- S1 完成后才分别实现 A/B/C/D；
- S2—S5 完成后才进行参数预实验和正式对照；
- 仿真结论与 S9 安全准备完成后才允许 S10；
- 不以旧 P1 是否闭环作为任何阶段的进入条件。
