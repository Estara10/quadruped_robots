## S1 研究合同与基础仿真闭环

目标：确认研究所依赖的关键接口和时间语义，得到可重复运行的基础仿真。

最小验收：

- observation/action、joint/action order、单位和模型输入输出一致；
- 实际 policy/RA 频率可测，hold 时间单位明确；
- A/B/C/D 状态机合同与配置字段冻结；
- 基础场景中 Agile、RA、Recovery 和指标记录链能够工作。

## S2 A 组原始单阈值基线

目标：记录原始策略在正常频繁切换背景下的行为和任务表现。

最小验收：

- 单阈值进入/退出和边界值行为正确；
- 运行时能证明 A 配置被实际使用；
- 至少在代表场景中记录 RA、模式、动作和短时反向切换现象。

## S3 B 组双阈值滞回

目标：只增加滞回，检验其对任务表现的独立作用及代价。

最小验收：

- 进入和退出阈值分别生效；
- B 与 A 除滞回外无有意差异；
- 对照切换、碰撞、到达、超时和推进，照实报告收益与代价，不以切换更少判定成功。

## S4 C 组 Recovery 最小保持

目标：只增加 Recovery 侧保持时间，检验其独立作用。

最小验收：

- 进入 Recovery 后实际保持时间符合设定；
- 到期后能够按单阈值条件退出；
- C 与 A 除保持机制外无有意差异，且无明显异常。

## S5 D 组组合机制

目标：组合已经验证的滞回和保持机制。

最小验收：

- D 同时满足 B 的滞回和 C 的保持语义；
- 不引入第三个未声明研究变量；
- 在代表场景中能完成一次稳定闭环运行。

## S6 场景与参数预实验

目标：确定正式实验的场景、参数和统计规则。

最小验收：

- 稀疏、中等、密集场景基本可达且有区分度；
- 选择进入/退出阈值、保持时长、短时窗口和超时；
- 冻结重复次数、种子/初态策略和无效 run 规则；
- 预实验数据不混入正式结果。
