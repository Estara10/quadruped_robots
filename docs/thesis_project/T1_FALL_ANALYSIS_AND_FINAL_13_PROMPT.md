## 4. 分析器修复原则

在实际生产 `scripts/s1_analyze_run.py` 的事件合并和任务窗口路径修复，保持单一生产实现。

- 策略帧时间、附带物理快照时间、事件起始/确认/关闭时间各有含义；不要求它们相等，不把物理快照时间改成策略时间。
- 允许同run、来源一致、历史完整的终止边界快照提供可追溯的历史事实。快照略晚于终止时刻时，按其中事件的明确时间判断任务期归属。
- 可信事件的 `confirmed_sim_time` 在任务窗口内，且事件身份与确认物理步一致时，可作为任务期跌倒正证据；快照发布时间本身不能抹去这一事实。
- 终止之后才确认的事件不能倒算为任务内已确认。终止后才关闭的候选也不能倒算为终止前已关闭。没有可用关闭时间或物理步依据时保持UNKNOWN，不能用后续closed标志猜测关闭时间。
- 准备期已关闭的事件不进入任务期跌倒结果；准备期开始、持续到任务且在任务期确认的事件按既定合同处理，不能一律丢弃。
- 来源冲突、时间/物理步矛盾、历史溢出、无效姿态等继续明确拒绝或UNKNOWN，不放宽现有校验。
- 明确区分“有可信历史正事件”与“完整覆盖下没有事件”。碰撞/跌倒为False仍须满足原覆盖条件，不能因为本次修复更容易得出无事件结论。
- 不把整个收尾快照的当前姿态、累计量、关闭状态不加时间过滤地回填到任务期；运动、站立、收尾的范围继续分开。
- 原始监督终局、记录有效性、派生安全结果分别保留。修复后才依据真实一致性决定分析终局，不删除冲突检查来放行。

尽量复用现有边界快照和事件历史，避免新增物理全量记录、协议扩展或通用事件框架。
