## 1. 我们现在研究什么

接受短时间内频繁、反向切换是现有策略的正常运行现象。不预设它有害，也不要求先证明它有害。

我们要回答的是：**在这种正常切换存在的情况下，加入双阈值、最小保持时间，能不能让机器人更少碰撞、更容易到达、更少超时？如果不能，代价是什么？**

切换次数和Recovery占比用于解释行为。次数少不是获胜标准，不再安排“证明短反向有害”的独立任务。原来480项实验的已报告结果和选参历史不改写，现存数据继续保留；M1已缺失的逐帧记录如实说明。

## 3. 第一步：先查清为什么撞、为什么超时

本步不增加仿真，只读已有M3记录。先看A组60次，以及C/D的16次超时；必要时对照同一张图其他组的记录。

### 碰撞看什么

看碰撞前有没有进入Recovery、碰撞时处于哪个模式、是否刚退出，以及当时RA、速度、位置、姿态和前方射线是什么情况。物理事件发生在两条策略记录之间、不能准确对应模式时，明确写“不确定”。

这些是寻找问题的线索。不能只凭“刚退出就碰撞”认定退出造成碰撞；也不能因为频繁切换就认定机器人出现异常。

### 超时看什么

先看机器人是在缓慢绕障、来回走，还是长时间难以前进。再看Recovery为什么没有退出：

| 当时情况 | 对下一步有什么帮助 |
|---|---|
| RA仍高于进入阈值 | 原单阈值也不会退出，缩短H未必有用 |
| RA已满足退出条件，但H还没到 | 值得检查保持是否过长 |
| H已到，但RA还没低于X | 值得检查退出阈值是否限制过多 |
| 两种限制同时存在 | 需要区分二者的作用，不能把问题全归给H |
| Recovery内一直推进困难 | 可能涉及已有策略能力，不能默认靠调阈值解决 |

代码还显示：每次进入Recovery时会重新优化恢复速度，驻留时复用缓存。长驻留是否使恢复方向不再合适，可以结合现有日志观察，但目前只是待验证解释，不修改这一控制行为。

### 这一步交付什么

两张简洁表：A组碰撞/超时情况、C/D超时原因线索；约6张代表性轨迹或时间图；最后给出一项建议：先改H、先改X、先改E，或者暂不调参。

完成标准是把情况说清楚，包括不知道的部分。**不需要找到正向效果才算完成。** 如果仍没有具体可检验的问题，就不进入新实验。

## 4. 第二步：有依据后，只改最相关的一项

优先使用少量现有开发图，不自动再造一套地图库。只有缺少某类必要布局时，才考虑少量新图；仍保留普通场景，避免只挑A失败的图。

### 如果主要是保持过长

建议先用4张开发图，比较A、C(H=0.10)、C(H=0.20)，各跑2次，共24项。其他条件相同。先回答缩短保持后，超时、到达和碰撞如何变化。

如果确实有必要，再在相同4张图比较B、原D(H=0.20)、新D(H=0.10)，各2次，另24项。原C/D保留，新设置单独标记。0.06、0.14秒只作后续候选，不一开始全部扫描。

H按有效仿真时间判定，到期后还要满足退出条件；约50Hz并不表示实际驻留必然等于整齐的周期数。

### 如果问题在进入或退出时机

进入太晚才研究更早接管；E从−0.05提高到−0.02反而会更晚进入Recovery，不能把方向理解反。改变E时还需说明退出值怎样设置，避免一次混入多个变化。

退出受限才研究X；RA轨迹是否处于候选阈值附近，也要先看清。若RA早已远低于候选X，小幅移动阈值可能根本不会改变决策。

具体候选值和运行数量在第一步结果出来后确定，不现在固定一张大网格。

### 怎样判断是否值得继续

主要看安全完成、碰撞、超时和推进；同时报告耗时和Recovery占用。切换增加不自动表示变差，切换减少也不自动表示变好。不调综合分权重来选赢家。

只保留一个有依据的优化设置进入验证；没有实际改善线索就结束，不继续扩图、加次数或扩大搜索范围。

## 5. 第三步：在没参与调整的新图上确认

只有开发比较出现值得检验的效果，才安排新图验证。

规模建议为12张新图，其中保留4张普通图；每张每组2次。保留原A/B/C/D，再增加1–2个优化配置，共120–144项。具体数量是建议，不是本次运行授权。

在看策略成绩之前固定地图、配置、比较方法和完成标准。不根据哪组获胜删图，也不在验证结果出来后继续使用同一批图调参。

继续使用安全任务完成作为核心指标，结合碰撞、超时、推进和耗时解释。每张图先汇总重复，再比较组间差异，报告不确定性。这一规模不能保证证明几个百分点的细小差别；结果不明确时如实报告，不自动扩大实验。

如果只改善某类场景，就限定适用范围；如果没有稳定收益，就报告约束的代价和能力边界。原M1/M3结果不覆盖、不改写，也不与新图混作独立样本。
