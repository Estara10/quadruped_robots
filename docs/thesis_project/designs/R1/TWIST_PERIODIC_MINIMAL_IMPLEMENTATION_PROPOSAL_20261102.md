日期：2026年11月2日

后续状态（2026-11-02）：Periodic实现已在当前运行中实际消费，P=0.06仿真秒、Frozen默认；MuJoCo查看器HUD绘制层级已修复并构建。用户随后明确授权challenge27单图40项A/C×Frozen/Periodic检查，该批40/40项完成并等待审阅，见[结果报告](../../evidence/R1/CH27_TWIST_UPDATE_40/20261102_r1_challenge27_twist_update_40/RESULTS_SUMMARY.md)。服务器实验和实机测试仍未启动或授权。以下保留原始方案和批准边界。

## 目的与范围

只比较Recovery期间Twist的更新时间：保留当前入口优化一次、随后复用的Frozen方式，另提供一个可选Periodic方式。两者继续使用当前Go2的同一优化函数和参数。

本方案不改E/X/H，不修正位移近似或梯度裁剪，不改RA、感知、Recovery网络、地图或任务条件。Periodic是待检验的更新方式，不预设它会减少碰撞或提高到达率，也不称为完整复现官方Go1实现。

## 建议的触发规则

| 项目 | 方案 |
|---|---|
| Recovery刚进入 | 保持现有行为：立即优化一次Twist，并作为本段起始指令。 |
| Frozen | 后续Recovery周期不重新优化，完全沿用现有缓存路径。 |
| Periodic首次更新 | 从Recovery入口的仿真时刻起算；达到周期后，在第一个仍处于Recovery的策略周期更新。固定候选周期 **P=0.06秒**，约为三个名义20ms策略周期。 |
| 后续更新 | 每次实际更新后，以当时仿真时刻重新计P。每个策略周期至多更新一次；若调度跨过多个周期，不连续补算或追赶。 |
| 更新所用数据 | 调用现有优化函数，读取该策略周期已有的最新RA、射线和机身状态；沿用当前优化初值、目标、限幅和迭代次数。 |
| 更新生效时刻 | 在该周期生成Recovery策略观测前更新，使该周期的Recovery推理使用新Twist。 |
| 与退出、H的关系 | 先按现有切换和H规则判定是否仍在Recovery。若本周期退出，则不更新；若H仍阻止退出，即使RA已满足退出条件，只要周期到期仍更新。H规则本身不变。 |
| 退出与重新进入 | 退出时清除本段更新计时；再次进入时重新从入口计算和计时。 |

P=0.06秒是单一的初始候选，不是最优周期结论。它让更新早于常见的0.10秒保持档，同时避免每个20ms周期都重算。阶段一数据不能证明所有场景都能等到首次更新；小批量必须报告首次更新前已退出的片段数及分母。如果更新机会太少，应如实判为检验机会不足，不通过延长H来制造机会。

## Frozen兼容

- 未显式选择方式时默认Frozen，原有实验配置继续走当前代码路径。
- Frozen下Recovery入口的优化时点、缓存值及后续复用行为不变；不为Periodic重构或改写共享优化公式。
- A/C与Frozen/Periodic作为两个独立因素记录。后续若开展小批量，比较A-Frozen、A-Periodic、C-Frozen、C-Periodic；同一切换设置内成对比较更新方式，避免把A-Frozen与C-Periodic的差异归给单一机制。
- 更新日志只记录必要字段：Recovery片段、更新类型（入口/周期）、策略周期与仿真时刻、计算耗时、更新后的Twist。每次周期更新一条简短记录，不逐策略帧输出长日志。该记录证明控制器计算并写入了值，不单独证明MuJoCo已消费命令。

## 计算成本检查

新增优化计时使用墙钟单调时钟；同时沿用现有策略周期记录，分开报告优化耗时与整个策略周期耗时，不能用后者冒充优化耗时。

小批量内按地图和条件报告优化耗时的中位数、P95、最大值，以及策略周期超过名义20ms的比例。以同一地图、相同切换设置下的Frozen为参照，预先采用以下筛查标准：Periodic优化耗时P95须低于20ms；若至少两张地图上Periodic的超周期比例高于对应Frozen，或出现可归因于更新计算的安全中止，就不进入服务器实验。单次偶发超时如实保留，不自动重跑。低于20ms只是必要条件，因为策略周期还包含其他计算。

现有Frozen策略周期本身已有超过20ms的记录，故不要求所有周期都小于20ms；重点是测量新增计算并与同期Frozen比较。上述标准只用于判断这个P候选是否值得继续，不代表硬实时保证。第一次实现阶段只能建立计时和输出字段，实际成本结论要等获准的小批量运行。

## 阶段二最小实现检查与成功标准

本方案已获有条件通过，允许最小代码实施、控制器构建和必要离线检查。实施仅限以下范围：

1. **Frozen兼容：**默认和显式Frozen均不触发Recovery驻留中的周期优化；入口及退出/重进语义保持现状。
2. **Periodic触发：**入口只计算一次；首次更新不早于P；到期后仅在仍处于Recovery的策略周期更新，且每周期最多一次；退出重进后计时重新开始。
3. **H未改：**复用既有切换逻辑，保持提前退出禁止、到期后仍须满足RA退出条件的现状。
4. **差异可见：**逐段能统计入口计算、周期更新、首次更新前退出与更新耗时；成功写入Recovery输入的Twist与记录相符。
5. **基本构建：**控制器构建通过；复用现有切换语义检查，并对“未到期、首次到期、连续到期、退出、重进”做一次针对性验证。不另建通用测试框架或运行门禁。

满足这些条件只表示实现按方案工作，不表示Periodic有效或计算成本可接受。成本和真实运动影响仍须在另行审阅通过的小批量中判断。若实现需修改共享优化公式或安全停止规则才能工作，应停下并重新审阅范围。
