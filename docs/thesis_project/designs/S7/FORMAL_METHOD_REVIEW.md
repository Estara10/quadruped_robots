### 1.2 地图、重复区组和调度

- 使用M1冻结1.0 `holdout01.xml`–`holdout30.xml`，不删图、不换序列归属、不重分难度、不按策略结果筛选。共30张地图×2重复区组×A/B/C/D=240计划项，每组60项。
- 对每张地图，每个重复区组均运行完整四组。采用四条Williams顺序平衡位置和一阶组别转换：`W0=A-B-D-C`、`W1=B-C-A-D`、`W2=C-D-B-A`、`W3=D-A-C-B`。60个地图×重复区组中每条顺序15次。
- 调度种子为`2026102001`。候选矩阵由[独立生成脚本](generate_formal_matrix.py)读取M1冻结索引生成，规则为：先按固定种子打乱30张图；对打乱后序号j的图分配`W[j mod 4]`和`W[(j+2) mod 4]`，使用同一随机发生器的随机位决定两条序列对应重复1/2；再打乱60个完整区组的执行顺序，区组内部顺序不变。该相隔2的分配使每种Williams序列在全批恰为15次，并保证同图两个重复使用不同序列；四组在四个区组位置各15次，12种有向相邻组别转换各15次。候选CSV/JSON：[formal_matrix_240.csv](formal_matrix_240.csv)、[formal_matrix_240.json](formal_matrix_240.json)。该矩阵在Director最终审阅前不作为正式运行已冻结计划。
- “重复1/2”指同一地图条件下的两次独立reset/起立/运行区组，不表示相同随机初态。M1 `layouts.json`中的生成种子固定的是地图几何；其`run_seed`为空。正式推荐调度种子控制任务顺序，不控制MuJoCo物理、策略或初始化随机源。只将已从代码/运行上下文实际确认的随机源列为受控；其余记UNKNOWN/未受控。
- 每个run执行相同MuJoCo reset和固定起立准入流程，真实策略进入后保存cycle0实际base姿态/位置/朝向、q/dq及session时间。初态异常门槛应在正式运行前固定；准备阶段异常完整保留，按统一规则判为准备拒绝或安全终局，不延迟任务窗口以隐藏它。记录实测差异，不宣称严格重放或组间初态完全一致。
- 留出集属于M1固定生成分布。只读核对`layouts.json`与`scene_index.csv`：30个唯一holdout scene均从`(0,0)`m出发、goal为`(7.5,0)`m、索引时限20仿真秒/120墙钟秒，边界均为x=`[-0.5,8.0]`m、y=`[-3.0,3.0]`m且不是实体墙；稀疏/中等/密集各10张，五种结构各6张。以上只是静态元数据一致性，不是策略可达证据。

### 1.3 统一运行条件

建议固定所有run：目标`(7.5,0)`m，到达半径`0.5m`；运动任务上限`20仿真秒/120墙钟秒`；ARRIVED后受控停止、站立观察`2仿真秒`，独立站立墙钟上限`30秒`；隐藏MuJoCo窗口、关闭RViz。运行使用同一代码、模型、观测/动作处理、控制频率、`0.30控制运行秒`公共启动增益交接、安全规则、场景版本与初始化程序。结果窗口从真实首个`rl_entered && rl_active`策略周期开始，终止周期包含在运动指标中；站立与清理分开。

M1 `layouts.json`静态核对支持上述目标和边界。其边界没有物理墙，机器人可能越出声明区域；推荐明确报告越界，不把地图边界描述为碰撞墙。

正式批次开始前一次性记录实际Git commit和必要工作区差异、三份关键模型身份、运行配置、MuJoCo版本、M1地图版本、参数、实际批次入口和统计代码。只对关键模型在有用时记录hash，不建立额外通用manifest。若运行中代码/模型/参数实质改变，先暂停并审阅影响，不静默换版本。

### 1.4 安全任务完成、终局和越界

**推荐的已确认安全任务完成：**在20仿真秒内达到目标半径；任务窗口内没有确认的非足端障碍碰撞、跌倒、系统安全中止或越界；与上述否定判断有关的记录、事件历史及时钟/物理覆盖足以支持判断。四个条件有任一UNKNOWN/覆盖不足时，结果是“到达但安全未定”，而非安全成功。

终局分类互斥报告：已确认安全到达；ARRIVED但安全或越界未定；碰撞终止；确认跌倒；其他系统安全中止；仿真超时；墙钟保护；准备/工程无效。保存原始supervisor terminal，另列记录有效性、motion safety和收尾状态。足端接触与足端撞击单独报告，不并入非足端障碍碰撞；站立观察/PASSIVE确认/进程关闭不能代替运动期任务成功。

**越界建议：**使用M1声明矩形x=`[-0.5,8.0]`m、y=`[-3.0,3.0]`m，边界值视为界内；以base_link的XY点作为明确可实现的范围定义，不冒称整机足迹包含。现有生产端`declared_boundary_physics_observation`可比较同run、同场景/模型的任务前和终止物理快照，依据PhysicsLoop每物理步累计的base_link越界计数及连续publisher覆盖给出任务窗口状态。任务窗口观察到任一越界物理步，标记“越界事件/非安全完成”；覆盖断裂、身份不一致、边界快照缺失或累计事件不能定位时标UNKNOWN。覆盖完整且计数增量为零，可支持“任务窗口内base_link在所有已覆盖PhysicsLoop步均在界内”；不能证明整机足迹始终界内，也不以离散策略采样保证物理步之间的连续轨迹。该方案复用已有计数，不为形式完整新建检测系统。

足端事件不改变上述主安全完成规则，但应报告足端接触次数、撞击次数与覆盖。安全完成不是“从未接触”。碰撞/跌倒否定结论只在相应完整任务窗口事件历史和覆盖充分时成立。工程无效与安全失败不能混为一类。

### 1.5 指标、分析与统计

**两个主报告指标：**(a)固定时限内已确认安全任务完成比例；(b)0.5仿真秒窗口的短反向切换频率（次/有效任务分钟）。对每组同时给计划项、实际启动、记录有效、结果UNKNOWN及分母。计时无效/周期缺口导致窗口不可判时不插值，报告观测次数和完整覆盖run数；不得用未知填零。

并列报告：ARRIVED/碰撞/跌倒/超时/安全中止/墙钟保护；任务有效连续时间、目标距离变化、路径及速度；全部模式边沿和有效时间边沿；Recovery有效时间占比、单次驻留分布、H到期后继续Recovery的退出条件、退出后0.5秒重入及可观察分母/删失；足端接触/撞击、base_link越界和UNKNOWN；周期/时钟覆盖、运行频率、站立观察与清理完成。模式边沿计数不因时间无效删除；有效时间指标仅按合同的连续有效区间计算。运动从首个有效策略周期到任务终止周期（含）；排除站立及清理尾段。

到达时间必须分开展示全部计划项/终局、ARRIVED子集时间，以及存在可比观察单元时共同到达地图/区组时间。后两项是选择子集，不作为总体加速证据。Recovery命令写控制接口不等于MuJoCo消费。可报告已记录RA风险边沿到策略模式决策的周期/时延，但只称内部决策延迟；没有同命令消费证据时，“动作生效/障碍响应延迟”保持UNKNOWN，不用纳秒函数时间冒充端到端响应。

每张图先对两个重复求组别统计，再对30张图等权汇总；四组和同图重复共同保留在地图cluster内。推荐地图簇bootstrap 10,000次、种子`2026102002`，对30个地图簇有放回抽样，每次带入该图全部组别和两区组，给主要差值的百分位95%区间。二元指标先形成每图组别比例再地图等权；连续指标同理先形成图级组均值。推荐以效应估计及区间为主，不做确认性显著性检验；如论文/Director要求p值，必须另行预先明确家族和多重比较控制，不事后挑显著结果。30个地图簇及两次重复不能支持统计等效或严格非劣效结论。

完整报告`B−A`（滞回背景）、`C−A`（保持独立作用）、`D−B`（滞回下加保持）、`D−C`（保持下加滞回）和交互`(D−C)−(B−A)`。到达/安全率以百分点差表示；短反向以次/有效分钟差；占比以百分点差；时间和路径用相同原单位的差值。交互按相应指标的差值尺度解释，不将二元率的百分点交互称为比值交互。固定报告所有对比，不按结果挑选。

对每个UNKNOWN指标同时给已知条件结果和全计划项情景范围。先统一计算数学差值范围`[候选下界−参考上界, 候选上界−参考下界]`，差值定义始终是“候选−参考”。“最不利/最有利”再依指标方向解释：越高越好时，最不利为数学下界、最有利为数学上界；越低越好时，最不利为数学上界、最有利为数学下界。对于有权衡、没有单一好坏方向的指标，只报告差值范围与背景，不贴最不利/最有利标签。说明已知条件分母（完整可判run）和全计划分母（60计划项/组）的区别；UNKNOWN情景界限是缺失结果敏感性范围，不是统计置信区间。

### 1.6 无效项、补做、暂停与资源

- 基础矩阵240个计划场景。建议最多12个有证据支持的工程替代启动（约5%），全批总场景启动上限252；同一计划项最多一次替代。额度不自动使用，且需要在正式执行任务再次明确授权。
- 场景创建前的编排/参数/overlay失败单独记attempt，不计实际场景启动；实际场景一旦启动便占启动额度。若合法任务碰撞、跌倒、超时、越界或安全中止，保留为结果、不替代。安全中止只有在独立证据证明由基础设施故障触发时才可能判工程无效，不能因为成绩差改类。来源冲突、采集器不就绪、任务帧/终止帧损坏等依预定标准判无效，原attempt和修复替代关系都保留。
- **两层记账（2026-10-19定向复核补充）：**计划项层每项只选一条按运行前统一规则确定的分析结果；未进RL的准备失败不产生导航结果；工程替代必须绑定原计划项、先前attempt、独立输出目录和授权，并受每项一次/全批12次上限约束。所有实际场景启动另列可靠性账，包括被替代的首次attempt、准备失败、运动安全中止、记录无效和清理异常。创建场景前的失败只进编排调用账，不进场景启动数。运行中断/恢复按attempt ID幂等去重，不重复算同一attempt；run_id、目录和组别冲突拒绝。
- **系统安全中止的替代证据：**veto记录证明安全停止发生及触发侧观测，不单独证明其根因是可排除的基础设施故障。只有绑定到同一run/事件、能独立佐证基础设施原因的记录，才可能允许替代。原中止永远保留在全启动层。正式报告另做“仅首次实际场景启动”敏感性；首跑未进RL列为未形成导航结果，首跑运动期安全中止不能被后续替代的较好结果抹去。
- **安全完成的缺失分母：**每组60计划项都报告已确认安全完成、已知未完成、安全UNKNOWN、未解决工程attempt、未解决场景attempt和未启动。全计划下界为已确认安全完成/60；上界只给尚无法确定结局的计划项一次性计入潜在成功。已确认碰撞、跌倒、超时、运动期安全中止以及无效记录中另有独立确认的安全失败均排除于该上界。INVALID本身不等于安全失败；没有独立安全失败证据时仍属未知。碰撞、跌倒等指标使用各自可判分母与情景缺失集，不能复用安全完成的缺失项集合。
- 纯说明标签错误不作为中断正在有效运行run的理由；在run间修正并保留更正记录。代码、模型或研究参数发生实质变化则暂停，不在同一冻结批次中静默切换。
- 推荐每12个场景或每个地图内的完整区组后检查数据/磁盘/进程账目；出现安全基础设施或来源/记录故障时立即暂停后续启动，定位并由Director确认后再按原冻结顺序恢复。恢复不重排已完成计划项，不重跑有效项，不静默更换代码/模型/参数。
- 某计划项的唯一替代仍无效时不再追加同项运行；保留失败并暂停批次，请Director决定未完成项的后续处理。
- 建议派生+原始批次预算6GiB，开跑前可用空间至少15GiB；T2常见规模估算约10–15MB/run，240加12替代约2.5–3.8GiB，留余量给runtime帧和图表。每次启动前检查剩余预算；触及预算或可用空间低于15GiB暂停，不删正式原始数据腾空间。
- 每次run后关闭并核实本次MuJoCo、controller/ROS、记录器与辅助进程；正常到达按受控停止路径并区分站立结束和实际进程退出。全批保留原始周期、安全producer记录、context、terminal、attempt台账及指标；派生表图不复制大体积时序。正式数据和开发数据分开，留出结果不得回流选参。

### 1.8 分析侧决策时钟重建（2026-10-21方法修订）

原分析方法只使用首个活跃策略周期 frame 的发布态 `sim_clock_valid`。新方法在同时满足以下条件时，使用**同一 cycle0** 的 decision-time 时钟作为任务时间轴起点：

- 首个活跃 frame 为 publication-stale（`sim_clock_status=STALE`，样本年龄超过发布新鲜度阈值）；
- controller-authored `S6-04-TRACE` 与原始帧属于同一 run/session/cycle；
- trace 在该周期 capture 时 `sim_clock_valid=true`，且 `sim_time_s` 与原始帧保留的样本在 1e-9 内一致；
- 原有 session、cycle、时间顺序、身份和异常拒绝条件继续生效。

匹配不成立、trace 缺失、sample 不一致、future/reset/identity 异常时保持原 `UNKNOWN`，不猜测。应用后：

- 原始 frame、JSONL、context、terminal 和旧 `metrics.json` 不覆盖；原始发布态 STALE、无效帧数和 age 保留；
- 任务起点仍是真实首个活跃策略周期，不移到后续周期；不插值、不借墙钟、不放宽控制器时钟新鲜度；
- 同一规则对 A/B/C/D 统一生效，不按组别、终局或结果是否有利选择启用；不改控制行为、起立准入、阈值、地图、模型或 240 项顺序；
- 正式分析同时输出 `task_start_clock`（原始/decision 两态）和 `reconstruction_sensitivity`（重建 run 数、安全分类改变数、主要时间指标改变数）。原始发布态口径可通过 `decision_clock_override=False` 复算，仅作敏感性对照。

该修订只改变分析口径，不改变仿真控制或正式矩阵。
