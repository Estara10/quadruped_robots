## 2. 建议保留的候选网格

| H（仿真秒） | 组别 | 设计用途 |
|---|---|---|
| 0 | A，无保持 | 同批单阈值参考 |
| 0.10 | C | 较短保持，观察能否减少单周期级来回切换 |
| 0.20 | C | 中等保持 |
| 0.30 | C | 较强保持，且已有实现核验经验 |
| 0.50 | C | 代价检查档，观察占用/超时/效率是否恶化 |

建议本轮不细化到0.01秒，不加入1秒以上长保持，不同时改变X。约50Hz策略对应约0.02秒的决策间隔，上表约为5/10/15/25个决策间隔，仅帮助理解；生产计时仍用实际MuJoCo仿真秒数，不按固定步数。

X=−0.10仅供未来B/D使用；A/C退出仍为RA<−0.05。C保持到期且风险满足退出条件才退出，不能到H就强制切回Agile。

## 4. 审阅后建议怎么跑

### 先做4次功能试跑

固定 **m02.xml**，使用A及C(H=0.10/0.30/0.50)各一次。选择依据是已有18图试跑中该图存在较多短反向事件，适合检查保持是否实际阻止过早退出；不是依据尚未产生的T2成绩选图。

先获准定向准备与检查，再启动；核对实际消费、计时起点、最短驻留、安全优先、周期记录及2秒站立收尾。碰撞、跌倒或超时不是工程故障，不为了得到ARRIVED重试。若没有足够Recovery事件，不自动加运行，报告证据不足。

### 再做180项A/C扫描

当前18张M2开发图×5档×2次=180项，其中A36项，C各H36项。两轮地图内平衡随机化，固定模型、地图、控制和安全规则；无窗口、RViz关闭，目标7.5m、20仿真秒/120墙钟秒，到达后观察2仿真秒。

不以T1的B记录代替新A。主规则沿用T2任务：相对A，到达下降≤5个百分点、碰撞增加≤5个百分点，确认跌倒与UNKNOWN单独审阅；短反向下降20%作实用改善参考，结合Recovery占比、足端撞击、超时与到达时间选择最小有效H。门槛是待冻结的工程规则，不是统计非劣效证明。

为避免“强制等H所以切换自然变少”被当作唯一成果，重点同时报告：到期后是否立即退出、驻留超过H多少、重入分母/删失、Recovery占用与任务代价。减少切换但到达退化不自动推荐。

### 选H后再做组合核验

A/B/C/D在6张预先指定开发图各2次，共48项。建议预先固定e03、m01、m02、d02、d05、d07：覆盖简单副作用、中等频繁切换、Recovery内碰撞、历史退化和退出后碰撞等已有情形；有目的选图，结果不估一般成功率。该清单在T2新结果前提出，待用户审定。

四组必须同代码同运行条件，B/D显式X=−0.10，C/D共用所选H。此阶段用于开发组合核验，不是正式留出测试。
