# 射线预测输入链路复核与有限动态观看

更新：2026-11-03。结论先行：**没有找到可直接修正的相机、预处理、标签、单位或束序代码错误；当前预测器在开阔方向的系统性低估和challenge27的大误差更符合模型/训练数据对当前输入—标签关系适应不足。完成授权的4次有限动态观看后，建议“实现问题未发现，当前模型应先做有限射线输出微调，再考虑扩展动态使用”。** 本轮权重、控制、地图、E/X/H与安全规则未变，也未训练。

## 核对结论

- **相机位置及跟随：** 当前预测器按`base_link`姿态计算相机中心`body_xpos + body_xmat·(0,0,0.27)`，即机身相对前/侧0m、高0.27m；朝向由动态机身变换后的前方点`body+(3,0,0)`确定。free-camera参数据此设`lookat`、距离、方位和仰角。几何上还原的中心射线俯角约−5.14°，水平FOV 102°，160×90对应垂直FOV 69.57°。这与当前MuJoCo微调数据生成脚本的相机函数相同。训练侧Go2配置记为x=0、y=0、z=0.27、单位四元数、`FOLLOW_TRANSFORM`。原始IsaacGym相机视图矩阵/标签同步图像没有随权重清单保留，因此不能证明基础预训练域和MuJoCo输入完全一致；没有证据支持改相机俯仰或平移。
- **图像证据：** 固定姿态challenge27图像中障碍02位于前向样本的图像中央附近；转向90°时相机随机身转动，障碍出现在相应侧向图像位置。机身上部轮廓留在图像底部，地面占据下半部；没有隐藏机身或地面。scene_flat无遮挡视野显示地面/远背景和机身轮廓。训练集现存深度样本也呈现地面/背景分界及底部机身形状，视觉布局相近；但没有逐样本相机姿态元数据，不能据此证明像素分布完全相同。例图见`scene_flat_fixed6/worst_samples/`和`challenge27_fixed6/worst_samples/`，这些是当前MuJoCo相机的真实深度渲染。
- **深度与网络输入：** 训练配置深度尺寸160×90、HFOV102°、范围0.1–6m。IsaacGym `IMAGE_DEPTH`为负的米制视线深度，采集代码取负并裁剪；当前MuJoCo renderer给出正米制深度，预测器裁剪至[0.1,6]m，做`log2`，单通道复制为3通道。微调`RayDataset`也对米制图像裁剪后取`log2`并复制3通道，未发现单位、通道数或变换次序错误。相机backend深度定义的跨域细节没有原始校准图可复核，保留为输入域局限。
- **标签与控制器几何射线：** 11束、角度−45°至+45°、步长9°，顺序由左至右；机身平面起点x=−0.05m、y=0，取水平XY中的最近距离并限幅[0.1,6]m。网络输出为11个`log2(m)`，写共享内存前转米制语义的同一`log2`值；控制器读入后按既有协议解释。微调标签由当前`generate_mujoco_ray_dataset.py`调用`compare_ray_pred.py`同一射线几何函数生成；标签来自场景选择的静态碰撞几何，排除地面plane与机器人本体，不是图像中所有可见物的深度。challenge27纳入7个登记障碍箱体；scene_flat没有障碍，11条标签均为6m。基础IsaacGym标签来自训练时`ray2d_obs`：半径0.4m的圆柱对象查询、z=0.1m射线起点，忽略地面与机器人本体。该目标定义不等同于相机可见深度，当前微调数据把目标重新定义为MuJoCo静态2D几何射线。没有因误差改变控制器射线定义。

## 冻结静态样本与同模型比较

查看输出前固定12个姿态：scene_flat `(x=2,6; y=0; yaw=0,90,180°)`；challenge27 `(x=2.5,3.8; y=−0.22; yaw=0,30,90°)`，高度沿场景默认站立qpos。位置/朝向清单见[FIXED_POSES.csv](FIXED_POSES.csv)，每样本恢复信息为`x,y,default base z,yaw`，不代表历史碰撞姿态复现。当前12姿态调用既有比较器；修复前后不存在代码差异，因此下表即当前固定输入下的模型基线，不伪造修复前后增益。静态比较在CPU上运行（本机该Python进程报告CUDA不可用）；动态阶段另用显式CUDA。

| 场景 | 样本 | MAE | RMSE | 最大误差 | false-safe | false-danger | 主要误差方向 |
|---|---:|---:|---:|---:|---:|---:|---|
| scene_flat | 6姿态×11束 | 0.582m | 1.058m | 2.662m | 0/66 | 18/66 | 第7–10束均值偏差−0.20/−0.41/−1.33/−1.81/−2.66m（距左至右编号0–10；前6束均为6m） |

沿用定义：false-safe需target≤1.5m且预测至少高0.5m；false-danger需target≥3m且预测至少低0.5m。challenge27反转束序后的MAE更差（2.604m，非2.058m），不支持左右反序错误。scene_flat几何参考11束全6m，固定样本显示偏差集中于末端右侧束；这是明确的输出偏短现象，不能简单归咎于障碍漏检，也不能通过隐藏地面/机身抹去。近障碍方面本组没有false-safe，不等于所有角度/姿态安全。

## 修改、判断与后续

本轮未修改代码、权重、控制器定义、地图或参数：相机位置/朝向在当前动态器与微调数据生成器中一致；深度范围、log2/三通道、11束顺序及控制器几何定义相符；固定图像可见障碍方向与朝向跟随合理。固定样本没有近障碍false-safe，但绝对误差偏大、开阔方向有系统低估，故判断为：**实现问题未发现，模型仍需有限射线输出微调后再考虑动态扩展。**

建议后续单独授权一次小规模ray-only微调：冻结Go2策略、RA/Recovery、地图和E/X/H；只用既有相机定义下的深度—几何射线成对样本，按场景/位置分组留出验证，避免同姿态泄漏；平衡scene_flat开阔方向与障碍近距/侧向束；继续用现有MAE、false-safe、false-danger门槛和输出时延指标评估。当前最大未知是MuJoCo微调图像相对原IsaacGym基础训练相机与材质/深度backend的输入差异，以及基础训练中圆柱标签和微调2D碰撞标签的目标差异。建议只调整射线网络，不重训Agile、RA或Recovery。
