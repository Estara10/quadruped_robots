## 对失败原因的判断

**一类情况与退出时机相符。** d02两次、d07和m01的最近Recovery退出RA只比A的−0.05退出线略低，之后0.042至0.548秒出现碰撞。尤其m01在RA=−0.053退出后0.070秒，碰撞前最后策略帧仍为Agile；同图B/C均2/2到达。这说明较严格的B退出线或C的0.20秒保持可能在短暂降险时继续维持Recovery，值得作为后续地图和X/H研究的具体线索，但不是因果证明。

**另一类情况不能用“退出太早”解释。** d01、d03、d05碰撞前最后策略帧仍是Recovery，RA分别为0.105、−0.043、0.044。这表明退出时机不能解释这些碰撞；恢复动作、行进路线或运行间差异都可能相关，现有数据无法确定具体原因。

d01的A失败轨迹尤其明显：目标距离从约7.5米降到约3.5米后，较长时间没有继续缩短，碰撞前最后策略帧为Recovery。该run记录了445次短反向切换；同图B/C代表轨迹的目标距离则持续降到到达范围。这里只是在这几次运行中同时观察到停滞与较多切换，不代表频繁切换一般有害，也不能证明切换减少导致了推进改善。

d08的A碰撞发生在RA已明显低于−0.10后约0.49秒，B组在另一重复中也撞到同一障碍、同一机身部位。这一案例不支持仅靠小幅放宽退出条件就能解决所有碰撞。

## 当前结论

M2结果给出的线索不是单一根因：部分A组碰撞前最后策略帧处于Agile，且此前不久刚退出Recovery；双阈值或保持时间可能延迟Agile重新接管。另有碰撞前最后策略帧仍处于Recovery，说明退出时机以外也有失败情况。现有结果支持继续研究这些具体场景，不足以断言B/C在一般环境中优于A。

后续高难度地图可优先参考d01的两段错位障碍和m01的斜箱、圆柱交错布局：它们既出现A组碰撞，也出现B/C到达。d03可作为Recovery中仍发生碰撞的补充布局。使用这些布局时，应保留所有组的结果，不按哪组更容易成功筛图。
