# R1-1：M3碰撞、超时与任务推进分析

> 阶段说明：R1-1已有数据分析已完成。本报告中的后续建议记录当时判断，不自动构成当前任务；当前安排见[R1任务](../../../tasks/R1.md)。

日期：2026-10-30。用途：M3既有数据的独立派生分析，不改写正式结果。源批次为`m3-abcd240-20261023`，正式结果表240项、A/B/C/D各60项；本轮检查A全部60项和C/D全部16项仿真限时记录，并读取同地图其它组结果作背景对照。

## 主要发现

**A组：**60项中44项确认安全完成，16项未安全完成：12次碰撞、3次仿真限时、1次系统安全中止。碰撞记录按任务期碰撞快照时间与此前最近策略帧分类：7次在Recovery内，5次退出Recovery后，0次发生在首次进入Recovery前。退出后碰撞的时间差分别为0.632、0.080、0.626、2.246、0.068秒；其中3次落在0.5秒描述窗口内。时间接近只说明事件顺序，不说明退出导致碰撞。A组失败逐run明细见[A组失败情况表](A组失败明细.csv)，60项终局与安全完成状态见[A组60次概览](A组60次概览.csv)。

碰撞并非都发生在同一策略阶段：Recovery内部与退出后碰撞并存。碰撞前最近帧可读RA、平面速度和目标距离，表中保留这些值。姿态角没有稳定逐帧字段可用于判断碰撞前姿态变化；碰撞快照中的姿态仅为离散快照，不能据此判断变化过程。M3-060为系统安全中止，不应误列作超时或碰撞。任务起点与碰撞时刻分别取正式分析任务边界和碰撞快照仿真时间，换算为任务相对秒数；若碰撞与策略帧未精确同步，按最近先行帧描述。

**C/D超时：**按正式报告数量核对为C组10次、D组6次，共16次。任务起点距目标约7.54米；超时结束时仍有约1.44至5.71米，未到达。各run任务距离总体下降，但部分推进有限或局部反复。Recovery占比约38%至49%；最长单次Recovery驻留多数不足1秒，M3-234为3.28秒。全部16次都存在保持时间到期后继续处于Recovery的记录；到期时RA仍未满足退出阈值，没有观测到“保持到期且RA已满足退出条件仍被H挡住”的帧。因此，这批证据更符合“RA仍不满足退出条件，Recovery继续运行”，而非单独由H锁住。到期后持续Recovery不等于Recovery一定没有推进；距离曲线显示多个run在Recovery反复进入退出期间仍持续接近目标。

各条距离、Recovery占用与到期状态见[C/D超时与推进表](C-D超时推进明细.csv)。时间图中的任务边界来自逐run正式分析字段；到达后的站立和清理片段不纳入分析。

- **challenge27（超时重复最多的地图之一）：**A两次仿真超时，C两次超时，D两次超时；B一次碰撞、一次超时。四组重复均未安全完成，说明该图对所有组都有挑战。C/D仍有净推进，但未到达。
- **challenge15：**A两次均碰撞；C一次超时、一次碰撞；D一次碰撞、一次安全完成；B也有一次碰撞和一次安全完成。重复间并不一致。
- **challenge01：**A一次碰撞、一次安全完成；C两次仿真超时；D两次碰撞；B一次碰撞、一次超时。此例显示同地图不同组终局不同，但初态并非严格重放。
- **A组M3-022（challenge08）：**碰撞发生在退出Recovery后约0.08秒，属于时间接近案例；同地图A另一次M3-003在退出约0.63秒后碰撞。两者均不能证明退出造成碰撞。
- **A组M3-014（challenge01）：**在Recovery内部碰撞，作为“不是退出后碰撞”的反例。
- **D组M3-234（challenge27）：**Recovery累计约10.68秒、占任务时长约49%，最长单次驻留约3.28秒；保持到期后RA仍不满足退出条件，最终距目标约4.51米。它提示长驻留和推进不足同时出现，但单例不能判定原因。

同地图记录是背景比较，实际初态并非严格重放，不能把轨迹差异归因于切换参数。M3地图经历史表现筛选，且部分来源与M1重合，不作为独立留出集。

## 结论边界

- **事实：**A组失败以碰撞为主；碰撞发生于Recovery内部或退出后。C/D的16次时限运行均未到达，均有保持到期后RA仍未达到退出条件的Recovery帧。
- **可能解释：**C/D部分运行在障碍附近持续风险偏高，Recovery也能取得一定推进，但未能在时限内完成。是否由Recovery策略能力、感知范围、局部路线或切换时机主导，现有记录不能分离。
- **不能回答：**碰撞是否由退出Recovery引起；H是否使整体推进变慢；改变X/E能否提高任务完成且不增加碰撞；姿态变化是否先于碰撞。RA和接触快照的时间/频率差异限制了更细因果判断。

## 下一步只建议一项

若继续做小规模开发比较，优先做**退出阈值X的局部比较**，而不是直接缩短H：在C/D超时中，H到期后仍不退出主要因为RA条件未满足，单缩短H没有直接作用。建议选challenge27（C/D重复超时且B也困难，压力场景）与challenge01（D完成而C超时，提供相反方向背景），比较原D（X=−0.10、H=0.20秒）和单变量D-X（X=−0.05、H=0.20秒），每图每配置2次，共8次。提高X会让`RA < X`更容易满足，可能更早退出；同时关注退出后碰撞，不能预设改善。正式执行前沿用既有开发图身份和运行记录，不新建地图。

主要看安全完成、碰撞、超时、终点目标距离、Recovery累计与最长驻留、退出后0.5秒碰撞窗口及到达耗时。若X改变没有实际改变退出时刻，或提前退出伴随碰撞增加/安全完成不改善，停止该方向，不扩大扫描；若结果方向不一致，也保留为不确定结果。**本建议仅为后续最小实验方案，本轮没有启动实验。**
