## 结果摘要

- 原始几何生成器 `s6-09-mapgen/1.0` 对固定配置和种子确定性生成布局、XML、逐图预览和检查结果；身份修复后的 ID 规则和可复现检查见 v1.1 补证报告。所有场景均有独立内部 scene ID、generation seed 和固定的数据划分；运行种子与布局种子分开。
- 开发与留出使用分离种子段；60 张种子互不重复。留出划分在任何策略运行之前写入库，本轮没有用策略表现筛选留出地图。
- 60/60 起终点直线均有实际障碍阻挡；15 个密度×结构组合均有 4 张图。全部路线满足 0.65 m Go2 保守包络加 0.10 m 工程余量的几何净距。
- 60 个 XML 均由 MuJoCo Python API 编译。C++ 生产场景探针对目录中的 71 张随机地图（旧随机地图 5、S6-08 样例 6、本批 60）逐一加载并通过模型指纹、障碍数量和 `selectObstacleGeoms()` 检查；Python `resolve_scene()` 对本批 60 张的场景身份绑定通过。
- 5 张路线结构代表图、开发集 30 张总览、留出集 30 张总览及 60 张逐图预览已生成。参考路线仅是几何核验/展示数据，不是机器人轨迹，也没有输入策略。

## 生成规则与密度

场地边界、起终点、障碍高度/尺寸、Go2 包络、余量、路径检查、密度定义和五类几何生成规则写在[地图规则](../../designs/S6-09/MAP_RULES.md)。障碍放置区域为 `x=[-0.5,7.5] m, y=[-3,3] m`，不是物理墙；参考路径搜索区域为 `x=[0,7] m, y=[-2.9,2.9] m`。起点 `(0,0)`、目标 `(7,0)`，起终点净空至少 0.95 m；障碍高度 0.32–0.62 m。

| 密度 | 障碍投影占地比例 | 最小障碍间距 | 本批实测占地范围 |
|---|---:|---:|---:|
| Sparse | `[6%,9%)` | 0.28 m | 6.00–6.67% |
| Medium | `[9.5%,12%)` | 0.16 m | 9.51–10.35% |
| Dense | `[13%,20%)` | 0.10 m | 13.00–14.40% |

三档互不重叠；档位间保留未归类间隔。占地、障碍间距、路线净距、路径长度和绕行比共同描述布局，密度不直接等于策略难度。每图障碍数为 6–12。实际障碍最小间距范围为约 0.102–1.440 m，按逐图形状轮廓计算。

路径检查使用 0.05 m、8 邻接网格，网格膨胀半径为 0.75 m 加半个网格对角线；简化路径再以实际旋转箱体和圆柱轮廓连续复核，采样间隔不超过 0.025 m，要求中心线最小净距至少 0.75 m。0.75 m 来自保持不变的 0.65 m 保守 Go2 平面包络半径及 0.10 m 工程余量。中心线包络宽度定义为参考路线最小障碍净距的两倍；本批为 1.502–2.030 m。此数值不是两侧障碍的实际间距。闸口的实际开口宽度另行记录；一般障碍之间的实际距离由其轮廓间距记录。圆形包络对机器人朝向旋转不变，用于整条路线及转弯段的几何检查，但并未经过 Go2 步态或转弯动态实测。

最初的生成草案将 Dense 下限设为 15%；不规则障碍群在 96 次有界重采样内无法同时达到该占地和 5 cm 网格连通。为满足“几何冲突时调整合理布局参数，不缩小安全余量”的要求，最终在任何地图接受和策略运行前，将统一密度档设为 Sparse `[6%,9%)`、Medium `[9.5%,12%)`、Dense `[13%,20%)`。保持了包络和余量；最终 60 张均满足新分档和通路要求。逐图实际占地、重采样次数及种子记录在布局 JSON 中，最大生成布局重采样为 92 次，上限为 96 次。

## 五类结构核验结果

| 结构 | 生成及核验规则 | 本批结果 |
|---|---|---|
| 单侧绕行 | 每图随机选择 +Y（图上左侧）或 −Y（右侧），障碍结构封闭另一侧。 | 12/12 路线位于声明侧且通过净空检查。 |
| 连续交替绕行 | 三个闸口中心方向符号连续变化，路线经过三处开口。 | 12/12 满足左右交替；开口实际宽度 1.95 m，逐路径净距通过。 |
| 错位通道口 | 三个开口至少取三个不同侧向位置，总跨度至少 1.5 m。 | 12/12 满足错位跨度、开口和路径净距要求。 |
| 多路线分叉 | 两条路线分别从两个选择障碍的上侧和下侧通过；在两个障碍位置横向分离至少 2.5 m。 | 12/12 保存两条独立参考路径；逐条净距通过，中心线间隔约 2.8 m。两条路线长度约 8.92–8.98 m。 |
| 不规则障碍群 | 障碍先随机放置，不围绕预设路线留通道；之后做连通及路径检查。 | 12/12 最终布局经 5 cm 网格连通和连续路径复核通过；无路候选被有界拒绝。 |

所有 60 张均有起终点直接线阻挡（要求至少 40 张）。这只说明地图几何符合类别约束，不说明参考路线是策略输入或策略必能走通。

图片交付包括 60 张单场景 PNG、5 张代表图和 2 张 30 图总览，共 67 张。单图比例轴按场地范围标注；图中路线和包络仅作几何展示。Director 检阅开发集总览后指出，同类地图仍有模板相似性，尤其连续交替绕行与多路线分叉；因此 60 张图不能解释为 60 种独立环境类型。

## 生产链和针对性验证

- 新增 60 条场景目录记录到 `common/abs_scene_catalog.def`。C++ 场景表由该共享目录自动推导大小，Python `scripts/abs_scene.py` 从同一目录解析；没有为每个场景增加独立分支。`scripts/s1_run_diagnostic.py --scene` 调用 `resolve_scene()`，现有批次入口将所选场景继续传给子运行器。
- Python MuJoCo 3.4.0 编译了全部 60 个 XML。生成器检查还逐图核对 XML、完整 include closure、障碍名集合、布局数据、逐图预览、代表图和总览可复现，并调用生产 `resolve_scene()` 验证场景 ID/根 XML/资源 closure 身份：60/60 通过。
- 共享 C++ `abs_scene::selectObstacleGeoms()` 在 ray2d writer（`unitree_mujoco/simulate/src/unitree_sdk2_bridge.h`）和碰撞 authority（`unitree_mujoco/simulate/src/obstacle_collision_authority.h`）中共同选择障碍。因此同一场景身份对应相同命名障碍集合，不把地面或机器人几何列为障碍。
- 重建目标 `s2_06_scene_probe` 后，对既有随机地图及新增地图运行 MuJoCo/C++ 生产选择探针，71/71 通过模型指纹、登记障碍数量、名称/类型/位置及 floor/robot 排除检查；其中新增 S6-09 为 60/60。`cpp_production_scene_probe.txt` 保存了逐场景及逐障碍输出。
- `scripts/test_s6_09_map_library.py` 针对性检查 60 张数量、15 个组合各 4 张、30/30 划分、种子独立、密度范围、障碍边界/净空/间距、每条路线的实际轮廓净距、五类结构不变量及直线阻挡，全部通过。执行记录见 `geometry_validation.txt` 和 `generator_check.txt`。
- 记录器和分析器使用通用 scene binding：`scripts/s1_run_diagnostic.py` 在准备/运行中绑定 `scene_id` 和 `resolve_scene().binding()`；`scripts/s1_analyze_run.py` 对 run context 与记录中的 `scene_binding` 作一致性检查。原地图库生成阶段没有启动 controller/策略；后续短 ID 修复补证对一张稀疏开发图实际验证了 publisher、reader 和分析链，其他59张尚无实际策略运行，详见[补证报告](S6-09_IDENTITY_REPAIR_REPORT.md)。
