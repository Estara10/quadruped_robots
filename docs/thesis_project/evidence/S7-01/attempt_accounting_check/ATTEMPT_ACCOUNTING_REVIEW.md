## 1. 核对范围与计数口径

“调用 attempt”“实际场景启动”“进入 RL 的运动任务”“计划项”和“被选作计划项分析结果的 run”是不同计数。一个场景在创建前失败仍是一次编排调用，但不是场景启动；场景已创建即消耗场景启动额度，即使没有 run_id 或未进入 RL。有效合法任务终局不因结果不理想而替代。替代是同一计划项的一次、预先有授权且证据支持的独立启动；所有实际启动仍进入系统可靠性报告。

旧 `logs/t2/...` 路径是兼容链接。本报告和 CSV 使用编号目录 `logs/02_T2_minimum_hold/...` 定位同一份原始证据，不双计。

## 3. 故障分类与替代证据

| 类别 | 统计和替代规则 |
|---|---|
| 场景创建前编排失败 | 单独计调用；不进场景启动或导航分母。须有进程/目录证据证明未创建场景，不能仅因缺run_id推断。 |
| 已启动、未进RL的准备/准入失败 | 消耗场景额度；保留正常安全拒绝、已证实基础设施故障、根因未知三类。仅有直接记录的工程原因才可能申请替代；不产生导航结果。 |
| 运动期合法终局 | 碰撞、确认跌倒、仿真限时、墙钟保护等按原结果保留，不因未到达而替代。 |
| 运动期系统安全中止 | 在所有启动层保留中止本身。只有与本run/计划项绑定、能独立佐证基础设施原因的证据，才可能进入替代资格；“无碰撞快照”、补做结果更好或看似竞争条件均不足。 |
| 记录损坏/身份冲突 | 同时报实际启动、终局/已确认安全事实和记录有效性。记录无效不能抹去已证实碰撞/跌倒；也不能猜缺失终局。无证实失败时安全任务完成保持UNKNOWN。 |

第34项可直接证明：controller在cycle 147触发安全veto；诊断字段记录同一奇序列状态被重读16次仍未形成稳定快照，故读路径触发有强直接证据。不能由此证明物理发布端没有同时发生真实异常，也不能证明veto时刻下游物理状态安全。稍后保存的LIVE物理快照不是精确veto边界；它当时未见碰撞、未分类接触或历史溢出，不足以倒推事件瞬间“无危险”。因此原因是“读取侧触发已证实、基础设施根因仅有限支持、物理危险排除未证实”。旧批次当时接受一次替代的历史事实保留；未来正式替代须满足本报告的独立佐证门槛。

## 4. 正式分母与无替代敏感性

### 计划项层：机制比较

每个正式计划项至多选择一个结果，选择规则在运行前固定且对A/B/C/D相同：有效合法任务终局保留；不依据组别、到达或表现替换。只有按前表证据确认可替代并经额度/授权批准的工程无效attempt，才可关联一次唯一替代；原attempt不能删除。替代仍无效时计划项保持未解决，不追加第三次。未进RL的准备失败不生成导航结果。

每组60个计划项分别列出已确认安全完成、已知未完成、安全结论UNKNOWN、未解决工程attempt、未启动。安全完成率必须同时报告：主全计划分母；有效且可判样本分母；以及缺失情景界。全计划安全完成下界为 `confirmed_safe / 60`；上界为 `(confirmed_safe + safety_unknown + unresolved_engineering + unresolved_scene_attempt + not_started) / 60`。各缺失类别分开列出且同一计划项只计一次。已确认碰撞、跌倒、超时或运动期安全中止均不进入潜在成功上界；记录无效但另有独立确认的任务期安全失败也不进入上界。其他指标使用各自可判事实和缺失集合，不套用安全完成的UNKNOWN集合。

有效合法任务未到达时，安全任务完成为False，即使碰撞/跌倒子指标仍UNKNOWN；系统中止不能冒充已确认的具体碰撞或跌倒。ARRIVED而任一必要安全证据UNKNOWN时复合结果为UNKNOWN。工程无效不自动变成安全失败。

### 所有实际场景启动层：系统可靠性

另按组/批次报告全部已创建场景的启动数、准备失败、已开始运动、各原始终局、安全中止、记录无效/身份证据冲突、工程替代、shutdown/进程退出异常。替代不删除首次attempt。启动层事件数不直接当作等时暴露下的风险概率。场景创建事实UNKNOWN单独列出，不能从已确认启动数中静默消失。

### 仅首次实际启动敏感性

另做非主分析：每计划项只看首次实际场景启动。首次未进入RL→“未形成导航结果/安全结论待定”；首次合法终局按原类别；首次运动期安全中止保留为安全任务未完成/原因未定，不能被后续到达抹去。该表是敏感性分析，不覆盖主计划结果，也不改原始记录。
