## 5. 功能结论

- **A仍无保持**：A overlay无保持字段，实际消费 `hold=false/H=0.0`，34次Recovery进出与单阈值行为一致；未引入保持行为回退。
- **C满足最小保持语义**：34个episode中0个在H前退出；到期且RA<E的episode均在到期周期或之后退出；4个到期但风险仍高的episode继续Recovery；6次风险回升没有重置入口时刻；34个episode各自重新计时；无效时钟/周期缺口为0，没有虚构保持完成。
- **A/C不配置B/D退出阈值**：四份overlay均无 `exit_threshold`；实际消费退出阈值均为E=−0.05。CLI的X=−0.10与A的H=0.30只是现有入口的校验回退值，未写入配置。
- **安全优先**：4项均正常到达，无安全中止、碰撞或跌倒；没有出现保持阻止急停/安全终局的证据。
- **代价方向（仅描述本次单次运行，不作参数比较）**：随H增大，本次运行的Recovery进入次数（34→16→10→8）、短反向（66→29→16→2）和任务时长（6.78→9.94→10.28→11.96s）呈同方向变化；Recovery占比约29%–34%，高于A的11.4%。每档只有一次，不能据此选H或推断总体趋势。
