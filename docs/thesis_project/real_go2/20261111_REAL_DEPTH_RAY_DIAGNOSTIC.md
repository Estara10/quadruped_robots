# 有线真实深度帧到 ABS 射线：离线诊断

## 问题与完成条件

有线跨机接收已经稳定，本轮用该次保存的4张真实深度帧检查模型输入、11束输出和CPU耗时。只读离线文件，不运行相机、ROS、VINS、共享内存或机器人控制。成功标准是说明真实输入能否直接使用，以及阻碍接入的具体问题；不以强行产生有效射线为通过条件。

用户本轮确认机器人目前趴伏、没有站起来；本轮无需站立。保存帧没有同步机身姿态记录，不能将其当成标准站立视野，也不能用本轮说明倒推采集时的精确姿态。

输入目录：`logs/real_go2/20261111_pc_wired_camera_aq3r_7yi/`。4帧为ROS `16UC1` 消息副本，单位毫米，乘0.001转换为米；没有将其当作SDK原始Z16，也没有猜测设备scale。原始文件未修改。

现有适配器保持原行为：对最后帧实际运行后返回2，拒绝7435个含未知深度的输出区域，没有生成 `.frame`。原规则要求每个缩小区域内所有源像素有效；因此“缩小后无效比例”高于原始零值比例，不能混用。

零值形成了大片区域，并非只有零散坏点。最近有效像素填充需要跨越最多约73–74像素，已可能跨越不同表面。少量原始值超过6m（4帧分别22、76、0、16像素），其中两帧含65535；诊断按现有模型范围裁剪，未将这些极端值验证为真实远距离。

## 两种处理仅作敏感性诊断

保留原严格适配器不变。在本次日志目录新增一次性分析脚本，比较：

1. `near_0p1m`：含未知深度的缩小区域填0.1m。这是输入近距离假设，**不保证神经网络输出保守**。
2. `nearest_valid`：在原图用空间上最近的有效测量填洞，再复用原有中心采样。没有把推算值称为真实测量。

使用明确的现有 `ray_pred_mujoco_finetuned_best.pt`，160×90、log2(m)、单通道重复3次、原范围[0.1,6]m。两种输入均输出有限的11项。逐帧两种输出最大差分别为0.675、0.938、0.961、0.784m；近值填充的某些输出反而更远，不能把它认作保守障碍探测。

所有结果均标记 `prediction_valid_for_control=false`，只写JSON和图像，不生成协议帧、不访问共享内存。原始观测及严格拒绝结果保留。

## 耗时与视场

使用系统NumPy1.21.5/SciPy1.8.0，再加载已有用户目录Torch2.0.1+cu118；CPU单线程，未安装软件或修改依赖。一次合成预热后，4帧×2种处理×5次模型调用：中位10.96ms，最小10.63ms，最大34.24ms。两种候选的合计预处理约42.8–45.3ms/帧，包含文件读取及现有逐区域采样。

这是离线模型与诊断处理耗时，不是持续15Hz链路延迟。本轮没有实时吞吐或源图像时龄结论。

该次CameraInfo得到水平光学覆盖约左44.58°、右44.33°，合计88.91°；当前 `scripts/ray_predictor.py` 仿真相机配置102°。102°是当前仿真入口值，本轮未重新确认权重的训练视场。直接拉伸图像不能增加可观测角度；模型输出标签仍为−45°至+45°，其真实物理方向与距离需结合相机视场、安装方向和目标对照验证。

## 结论与下一步

真实帧能经过显式诊断预处理得到11束预测，当前CPU模型调用耗时较短。**当前主要问题是原始深度大面积缺失及输入视场适配，不能靠随意补洞解决。** 暂不改模型、严格适配器、控制器或仿真。

下一步建议一次静态原始深度质量对照：沿用有线和唯一pipeline，在相同姿态/场景下只改变投射器开关，比较零值分布与双IR/IMU连续性。优先判断能否改善原始输入，再确定最小预处理；同时记录相机姿态。该对照尚未执行，投射器对VINS特征的影响也需在联合验证时检查。

本轮分析已退出，没有启动设备、ROS或控制进程；不改变R1任务、A1工程或ABS实机运动NO-GO状态，未提交Git。
