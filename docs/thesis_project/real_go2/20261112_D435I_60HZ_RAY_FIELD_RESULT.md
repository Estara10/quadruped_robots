# 60Hz深度→诊断射线现场观察结果

后续第三组及三组原因审阅见[三朝向统一报告](20261112_THREE_HEADING_DEPTH_RAY_REVIEW.md)。本文件保留前两组的详细记录。

## 做了什么

用户开机并授权测试。使用新增只读观察器 `scripts/go2_depth_ray_observer.py`，在现有有线链路上接收深度、CameraInfo并进行CPU单线程推理。相机唯一pipeline：480×270@60深度＋双IR、gyro200／accel100合并IMU、同步开启、投射器开启。观察器不写协议帧、共享内存或任何控制数据；没有启动VINS、策略或机器人控制。

采集目录：`logs/real_go2/20261112_024050_depth_ray60_readonly/`。观察窗口42.007秒，其中实际收图约34.7秒。观察器模型预热后建立订阅，第一次5秒摘要确认就绪，再启动相机。相机限时46秒，观察结束后再恢复投射器0并停止相机，避免开关变化混入统计。

输入为ROS 16UC1毫米深度；向量化中心采样，显式0.1m未知格诊断占位，始终标记不适用于控制。未解决约89°相机视场与102°微调数据差异，不能用本次性能结果证明射线物理准确。

## 本次发现与未验证项

- PC接收上限重启后恢复208KiB；主助手非交互sudo失败后，用户手动恢复8MiB，启动器检查通过后才开始实际采集。未修改默认缓存或持久配置。
- 观察器已在主线程预热模型，首张真实工作帧仍出现约201ms模型调用。这是实际启动延迟，不能用稳定段中位数掩盖；需要交给执行器检查工作线程预热或初始化路径，保留原始慢帧与覆盖计数。
- 日志出现一次启动Motion Module failure通知（2行）及HID、默认IMU标定警告。本次只订阅深度和CameraInfo，没有验证双IR／IMU实际接收质量或VINS。没有将告警归因为本次CPU处理。
- Orin源header仍与PC墙钟不一致。上述延迟只表示 **PC收到图像后到射线计算完成**，不包含曝光、USB、跨机传输或机器人响应；源采集到电脑时龄明确留空。
- 本次没有独立障碍方向／距离真值，没有保存相机像素图，因此不报告射线精度；占位和视场仍限制物理解释。机器人具体站立／趴伏未由本轮状态订阅核实，仅要求用户保持静止。

## 启动失败记录

第一次准备目录 `logs/real_go2/20261112_023841_depth_ray60_readonly/` 的现场启动器在干净PATH中调用不可用的rg，就绪检查失败，相机未启动、收图0。主动SIGINT结束观察器时，清理写出结果后抛出ExternalShutdownException。记录已保留，不能视为有效相机试验。

现场启动器改用系统自带/bin/grep并另建目录后完成本次采集；中间一次拼接时间目录的启动命令未找到脚本，没有启动进程。未修改观察器生产代码来掩盖失败。SIGINT异常可随实际启动慢点一并交给执行器最小修正；正常到时退出本次为0。

## 收尾与下一步

观察器退出0，相机外层timeout124（计划限时），日志确认SIGINT后关闭传感器。投射器恢复0返回成功；参数恢复查询创建的Orin域42 ROS daemon已单独停止，再次检查PC和Orin均无本次相机、观察器、VINS、rosbag或ROS daemon匹配进程。

没有保存相机图片或录包，只保存逐帧统计、配置、日志及一张统计曲线图；未修改模型、控制器、仿真、R1、A1或系统持久配置，未提交Git。

下一步：先让执行器针对已出现的首帧201ms和SIGINT异常做最小离线修正；现场随后用方向、距离已知的障碍检查射线物理输出，再考虑投射器开启条件下VINS联合观察。当前不启动ABS运动或2m/s测试。

## 第二组：换朝向复测

用户自行换朝向并就位，保持同一相机／模型／占位配置，另建目录 `logs/real_go2/20261112_025107_depth_ray60_heading2/` 进行一次42.005秒观察。深度接收2114帧，处理及输出2107组；处理错误0，处理header全部唯一，源header重复及回退均为0。实际朝向角、姿态及障碍真值未测量。

第二组仍无UDP接收错误、缓存溢出及Frame resources错误；未出现Motion Module failure通知，IMU默认标定警告保留。新朝向的深度完整度发生变化，本地计算吞吐仍接近60Hz；不能将两个未测量场景的差异分解为具体表面、曝光或遮挡因素，也不能据此认定诊断射线距离准确。
