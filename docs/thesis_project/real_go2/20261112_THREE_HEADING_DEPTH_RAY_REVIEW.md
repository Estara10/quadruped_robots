# 三个朝向的60Hz深度与诊断射线：统一审阅

## 要回答的问题

用户连续更换朝向，保持相同60Hz配置，检查深度缺失是否随场景改变，以及是否来自接收或电脑处理跟不上。第三组额外授权保存少量图像用于解释空洞分布。

三组均为D435i→Orin USB2→有线→电脑、480×270深度＋双IR、合并IMU，投射器开启；电脑CPU单线程运行同一Ray-Pred、相同中心采样和0.1m未知占位。只订阅深度与CameraInfo做诊断，未运行VINS、策略或机器人控制。没有实测朝向角、固定场景照度、曝光参数或障碍真值，不能当作严格控制的光照或材质实验。

## 第三组样本：直接看到什么

在第三组性能观察器退出后，另启动一个有限5秒的一次性ROS订阅者，在原相机pipeline中保存 **一组同header的深度＋左IR＋右IR**。三路各收到1张即匹配成功，没有连续存图、没有第二个相机SDK pipeline，也不影响前面的性能测量。

样本header为504618850221082ns。IR画面可见桌椅边缘、远处物体和一片很亮的背景；投射点阵可见。像素图的精确IR—深度注册未另行验证，因此只作场景及大尺度区域背景，不逐像素判定材质原因。

- 该张深度全图零值20.459%，中央ROI零值14.25%，与第三组持续统计量级相近。
- 约80.43%的零像素属于接触图像边界的连通区域；最大三个缺失连通块为9982、6345、4424像素。不是只有零散坏点，中央也有空洞。
- 上／中／下三分之一区域零值分别约28.40%／12.96%／20.02%；左／中／右三分之一区域为16.88%／14.54%／29.95%。
- 左IR中有5209个255饱和像素，强亮背景的曝光问题值得作为候选检查；遮挡、距离、纹理也可能参与，单组图不能分解各自贡献。
- 深度有16570个像素超过模型6m范围，其中398个为65535mm；非零深度P95为10.283m。这些在当前输入中会被裁剪到6m，本轮没有判定它们是可靠远距还是错误匹配。**非零比例不等于可信测距比例。**

## 原因判断

1. **本次没有显示出USB／网络接收或持续推理积压是图内空洞主因。** 三个朝向的零值比例大幅不同，但频率均约60Hz、稳定段耗时接近、UDP接收错误和缓存溢出为0、覆盖只在启动期发生。换USB3或提高电脑推理速度不是当前解决这类零值的首选。
2. **证据支持场景相关的相机测深条件影响完整度。** 第三组样本包含成片亮区、远处背景及物体边缘；官方说明双目深度空洞可来自遮挡、纹理不足、重复匹配、曝光不适或过近距离。投射器之前的开／关对照也已验证纹理辅助对原场景有明显帮助。这里支持这一类原因，不能进一步宣布每片空洞都由反光或曝光导致。[RealSense官方空洞说明](https://dev.realsenseai.com/docs/depth-post-processing-for-intel-realsense-depth-camera-d400-series/)
3. **启动约200ms慢点具有重复性。** 三个不同朝向均只在首个工作帧出现，随后约13ms；当前模型只在主线程预热一次。优先让执行器离线检查JIT／工作线程初始化路径，不把根因先定为某个线程机制，也不删掉慢帧来制造通过。
4. **射线物理正确性仍是下一阶段问题。** 当前约89°／102°视场差异和未知占位未解决；不同朝向的真实障碍本就不同，不能仅比较11个输出值的变化来判定模型错或对。必须增加独立的已知方向／距离参照。

## 下一步

已有三组足够暴露“场景质量变化＋启动慢帧”，不自动继续换朝向采集。建议执行器针对启动慢点与SIGINT异常做最小离线修正，并审阅第三组实际样本中的未知／超范围语义；随后由主助手安排一次静态已知障碍方向、距离对照，验证射线是否看得对。VINS联合负载及低层运动仍另行验证，不因本轮60Hz通过而直接进行2m/s运动。
