# D435i 射线适配数据准备与下一轮训练命令（2026-11-15）

## 结论

本轮在离线环境用已修正主点的生成器，生成了一批**1200 个独立几何位姿、2400 张 clean/masked 输入**的适配候选数据，按 8/2/2 个完整布局分为 train 840、validation 180、test 180 个位姿。标签全部由场景几何独立计算，未训练模型、未连接机器人/相机/服务器、未初始化 ROS/DDS、未写共享内存。数据在 `logs/real_go2/20261115_d435i_ray_adaptation_data/adaptation_v1/`，约 136.7 MiB。

本轮同时核对了训练与现场候选预处理，确认数值流程一致；仍存在三类不一致：现场默认严格入口不使用 6 m 填充、现场 SDK 版本与离线补洞实现不同、真实相机噪声/材质和合成场景不同。近障视野限制依旧存在：±45° 标签交点始终画外，±36° 近侧（<1.5 m）也全部画外；这些限制不由增加训练量消除。

## 一、训练与现场处理流程核对

| 环节 | 训练数据（本批） | 现场观测器候选 | 是否一致 |
|---|---|---|---|
| 深度单位 | 渲染米值 → mm `uint16`，再乘 0.001 回米 | ROS 原始深度 mm × 0.001 | 一致 |
| 未知像素 | 真实原始零值掩码移植到合成 Z16 | 设备原始零值 | 只是增强，不是同一物理空洞 |
| 补洞 | `librealsense 2.58.4` `holes_fill_farest` 源码等价实现（mode 1） | Orin SDK 2.51.1 mode 1 | 算法同一族；有限保存帧曾逐像素一致，**不能泛化为所有版本/帧等价** |
| 残余未知 | 0 → 6 m | 观测器 `--unknown-fill-m 6` 时 0 → 6 m；默认不填并跳过该帧 | 本批对应“候选填充策略”，不对应默认严格入口 |
| 中心采样 | `480×270 → 160×90`，源像素 `(3i+1, 3j+1)` | 同一中心采样 | 一致 |
| 数值化 | clip 0.1–6 m → `log2` → 复制 3 通道 | 同左 | 一致 |
| 11 束定义 | 角度 −45°…+45° 每 9°（索引 0…10），起点 base 前向 −0.05 m、机身水平面，范围 0.1–6 m | 同一 ABS 合同 | 一致（本轮未改） |
| 标签来源 | 场景几何求交（`mj_ray` 独立复核） | 无逐束真值；相机中心深度不能充当标签 | 训练专属 |

补充事实：现场默认严格入口要求 3×3 源足迹全部有效，否则拒绝该帧；候选路径只在被采样中心仍未知时填 6 m，并标记 `prediction_valid_for_control=false`。本批 masked 输入按“补齐后中心值 + 残余零→6 m”构造，与候选路径的**数值**一致，但不是默认入口会接受的数据分布。训练 clean 输入无空洞、无真实传感器噪声，现场不会出现。

## 二、实际生成内容

- 驱动脚本：`scripts/prepare_d435i_ray_adaptation_data.py`（新增；复用 `scripts/generate_mujoco_ray_dataset.py::render_depth` 的修正主点路径、`compare_ray_pred.py` 的几何标签与采样、现成 mode 1 补洞与 `downsample_depth_centers`）。
- 输出：`logs/real_go2/20261115_d435i_ray_adaptation_data/adaptation_v1/`
  - `data/{train,validation,test}/`：1680 / 360 / 360 个 `.npy`（90×160）与各自 `label.pkl`；
  - `scenes/`：12 个布局 XML（含 train 8、validation 2、test 2）与 2 个诊断场景；
  - `ray_projection_visibility.csv`：1200 位姿 × 11 束 = 13200 行；
  - `data_records.json`、`summary.json`、`run.log`；
  - `geometry_checks/`：中心/左右/边缘已知目标投影检查；
  - `diagnostic/`：0.25 m、0.35 m 中心目标，明确排除于 train/validation/test。
- 生成耗时与占用：小样本探针 48 位姿 10.5 s、5.86 MB；全量 1200 位姿 228.7 s，文件合计约 136.7 MiB（`.npy` 132.1 MiB），`du` 磁盘占用约 146 MiB。本机 45 GiB 可用空间充足，无需连接服务器。
- 位姿参数：x∈[−0.8, 3.5] m，y∈[−1, 1] m，yaw∈[−0.5, 0.5] rad，base 高度 0.350–0.360 m，下俯 3.0–5.0°。相机壳体代理位置 (0.305, 0, 0.140) m、内参 `480×270, fx=fy=244.134, ppx=245.186, ppy=134.22` 未改。
- 掩码来源按完整集合分开、互不共享：train 12 帧（remounted、remount_adaptation、existing_mount_standing、1 m 各 3 帧）；validation 3 帧（80 cm）；test 6 帧（2 m 与 2026-11-12 native_fill_field 各 3 帧）。同一掩码帧在 train 内被多个位姿复用，这是增强的已知局限。

### 位姿分布控制

按每个布局的 near/mid/far 位姿配额做拒绝采样，单一位姿需至少 2 条近/中/远束，且 6 m 截断束不超过 5–6 条；近障标签占比不再由远处样本主导。实际位姿类别（near/mid/far）：

- train：415 / 266 / 159
- validation：67 / 62 / 51
- test：67 / 62 / 51

布局覆盖近障、左右偏置、遮挡对（前后同向箱体）、走廊、开阔与随机布局；训练/验证/测试按整布局划分，配对样本不跨集合。

## 三、最小几何检查

### 1. 图像-标签配对、单位、束序

- 1200 个位姿均有 clean/masked 两张图，标签 11 维、单位米；图像形状 90×160、有限、范围 [0.106, 6.0] m；无空渲染帧（全 0.1 或全 0 会被脚本拒绝）。
- 13200 条标签逐条与独立 `mj_ray` 三维水平射线复核，最大允许差 1e-4 m；全部通过（脚本遇差即停止）。
- `clean` 图由 `native` 经既有 `downsample_depth_centers` 中心采样生成（与生成器默认非 native 分支同一函数）；`masked` 与 clean 共用同一独立标签。

### 2. 中心/左右/边缘目标投影

每个目标单独成场景，位姿 x=0、y=0、z=0.36 m、yaw=0、下俯 4°：

| 目标 | 标签 | 投影 u (px) | 画内 | 模型输入深度 / 投影光学 z |
|---:|---:|---:|---|---:|
| 0°, 1.0 m | 1.000 m | 245.186 | 是 | 0.653 / 0.653 m |
| +18°, 1.2 m | 1.200 m | 131.19 | 是（左半） | 0.793 / 0.794 m |
| −18°, 1.4 m | 1.400 m | 352.54 | 是（右半） | 0.984 / 0.984 m |
| +45°, 2.0 m | 2.000 m | −78.57 | 否 | — |
| −45°, 2.2 m | 2.200 m | 559.71 | 否 | — |

其余 10 束在这些单目标场景中均为 6 m 截断，束序、左右符号与标签距离一致；模型输入深度与投影光学 z 在画内目标上差 ≤1.5 mm。

### 3. 深度-投影一致性（全量）

8324 条“交点画内”记录中：92.1% 的模型输入深度与投影光学 z 差 ≤2 cm；5.3% 的输入更深（被更近表面遮挡，合理）；46 条（0.55%）输入比投影更远 >10 cm，最大 4.77 m，集中在掠射/轮廓边缘，属离散采样与遮挡边界，不是系统性主点偏移。该列只能作审阅，不能当作逐像素真值。

| train | 18.5% | 25.7% | 36.5% | 19.4% |
| validation | 14.5% | 24.0% | 34.2% | 27.2% |
| test | 14.3% | 21.3% | 39.3% | 25.1% |

## 五、下一轮有限训练命令（本轮未运行）

训练器复用 `scripts/finetune_mujoco_ray_pred.py`，medium 起点，固定 4 轮、仅更新 `layer4+fc`、batch 32、lr 1e-4，输出到新的 run 目录，不覆盖旧权重。命令中的路径均为本机真实路径：

```bash
cd /home/lidio/quadruped_robots
/home/lidio/anaconda3/envs/abs/bin/python scripts/finetune_mujoco_ray_pred.py \
  --base-model archive/ray_pred_finetune/mujoco_finetune_medium_20260611/ray_pred_mujoco_finetuned_best.pt \
  --datasets logs/real_go2/20261115_d435i_ray_adaptation_data/adaptation_v1/data/train \
  --validation-datasets logs/real_go2/20261115_d435i_ray_adaptation_data/adaptation_v1/data/validation \
  --test-datasets logs/real_go2/20261115_d435i_ray_adaptation_data/adaptation_v1/data/test \
  --validation-visibility-csv logs/real_go2/20261115_d435i_ray_adaptation_data/adaptation_v1/ray_projection_visibility.csv \
  --test-visibility-csv logs/real_go2/20261115_d435i_ray_adaptation_data/adaptation_v1/ray_projection_visibility.csv \
  --output-root logs/real_go2/20261115_d435i_ray_adaptation_data/training_runs \
  --run-name d435i_medium_layer4fc_20261115 \
  --device cpu --trainable layer4_fc --epochs 4 --batch-size 32 --lr 1e-4 --num-workers 0
```

服务器版本只需替换 `REPO`/`DATA_ROOT`/`RUN_ROOT`/`PYTHON` 为绝对路径并把 `--device cpu` 改为 `--device cuda:0`；`cuda:0` 不可用时停下检查环境，不静默回退 CPU。

选模规则（训练器已实现）：每个 epoch 先通过非回归门槛——验证集 false-safe 数、false-danger 数、近障高估 P95 三项均不差于 medium 验证基线；合格轮次再按总体 MAE 最小选择，平手按近障高估 P95 较低。test 只在选模完成后报告一次，不参与选轮。**只有总体 MAE 下降、近障高估变差时不能宣布适配成功。**

## 六、明天现场最少确认

只列会影响本批数据或模型评价的事项，不预设通过阈值，也不要求连接 ABS 控制：

1. **安装是否变化**：确认相机壳体仍约在 base 前 0.305 m、左右 0 m、上 0.140 m，下俯约 3–5°，站立 base 高度约 0.35–0.36 m。若支架或角度变了，记录新值，并把这批数据标记为“旧安装候选”，不能直接当作新安装的匹配数据。
2. **实际 profile 与内参**：确认深度流为 480×270、实际帧率与深度 scale，读取 `camera_info` 的 fx/fy/ppx/ppy；确认标定是否仍为零畸变、深度与 IR1 是否同内参。若与 (244.134, 245.186, 134.22) 不同，记录差异，不静默沿用。
3. **补洞与相机设置**：记录 Orin 上 librealsense/SDK 版本、是否 mode 1、投射器/自动曝光设置；保存少量原始帧与补洞帧成对样本，供离线对照（不要求本轮重做逐像素比对）。
4. **站立状态下的简单可测障碍**：用卷尺量取并标出起点/终点，记录至少前方约 0.8 m、1.5 m、2.5 m 平整目标，以及左侧、右侧各一个约 1 m 目标；只保存深度/IR 与图像，不运行模型或控制。
5. **近侧可见性**：记录 ±27°…±45° 方向的近目标是否进入画面；这决定对应束能否被直接观测，不要因画外就判模型错误。
6. **参考点提醒**：ABS 11 束起点是 base 前向 −0.05 m 的机身水平面，相机中心深度不能直接当作机身 11 束标签；比较时必须先做几何换算。

## 七、本轮发现的两个生成器问题

1. **上一小批检查数据首帧为空**：`20261113_d435i_ray_next_training_preparation/candidate_v1/data/train/scene00_pose00000_clean.npy` 实际全为 0.1（首帧渲染返回 0，被裁剪到 0.1），另 7 个位姿正常。该小批仅用于几何审阅、未参与训练；旧文件保留不改。本轮驱动在创建渲染器后先预热一帧，并对每帧做“全近”有效性检查，必要时重渲染一次，仍异常则停止。
2. **前次分割可见性统计的渲染器未设置候选 fovy**：上次小批的 `obstacle_has_visible_pixels_in_render` 在未设置 `model.vis.global_.fovy` 的进程中渲染，投影与实际深度图不一致，相关计数不可直接复用。本轮在创建分割渲染器前已设置候选 fovy，并对画内交点的深度-投影一致性做了全量统计（见第三节）。

## 八、未完成与边界

- 本轮未训练、未推理候选权重、未评价模型精度；训练命令仅整理，未执行。
