# ABS射线消费与下一轮评价口径

2026-11-16；只读源码审阅，未运行模型、ROS、仿真或设备。本报告不改变配置或实机许可，不改R1任务。与相机安装几何核对分开记录。

## 1. 已确认的输入与切换

| 项目 | 当前源码/默认配置含义 |
|---|---|
| 深度网络输入 | 深度米值裁剪到0.1–6 m，log2，复制3通道；相机空洞处理须另行明确 |
| 射线载荷 | 11个log2距离；`ray_predictor.py`把网络输出裁剪到log2(0.1)–log2(6)后写共享内存 |
| 控制器读取 | `StateRL::updateRay2d()`直接复制载荷，不再取log2，也不转回米 |
| Agile | 61维，最后11维是射线；整体clip_obs=100，对正常射线log2范围不产生额外裁剪 |
| RA | 19维：机体系线速度3、角速度3、目标命令前2维、射线11；射线没有再次缩放 |
| Recovery | 49维观测不含射线；射线通过RA切换和安全twist优化间接影响恢复行为 |
| 默认A组 | RA≥−0.05进入Recovery，RA<−0.05返回Agile，无滞回、无最小保持 |
| B/C/D | B：进入≥E、退出<X；C：单阈值加保持；D：双阈值加保持。具体E/X/H以运行配置为准，不用历史批次参数代表当前实机 |
| 输入失败 | 缺共享内存、帧不一致、时间异常、过期或非有限等导致读取失败；runModel调用safetyVeto。本路径不证明机器人能够制动或停稳 |

没有固定的“距离小于某米就切Recovery”规则；RA是状态、目标与11束共同决定的神经网络输出，不能把−0.05换算成一个固定障碍距离。也不能预设某束距离变大必然使RA单调变小。

源码入口：
- `scripts/ray_predictor.py`，`scripts/go2_depth_ray_observer.py`：后者把log2输出exp2为米供诊断显示，不发布控制帧。
- `quadruped_ros2_control_humble/controllers/rl_quadruped_controller/src/FSM/AbsObservationContract.cpp`：Agile/Recovery/RA拼接。
- 同目录`StateRL.cpp`：updateRay2d、runRAModel、runModel和切换调用。
- `quadruped_ros2_control_humble/controllers/rl_quadruped_controller/include/rl_quadruped_controller/FSM/RASwitchingLogic.hpp`：切换不等式。

## 2. 频率与时龄应怎样理解

仓库Go2 `config/robot_control.yaml`的RL控制器update_rate=200 Hz；`config/abs/config.yaml`的decimation=4，源码从控制器update_rate读取frequency_，同步路径每4次调用runModel，因此默认名义策略/RA频率为50 Hz、周期20 ms。controller_manager的1000 Hz不是策略频率。配置中的“25步约0.2秒/125 Hz”旧遥测注释与这组默认值不符；默认值下25步为0.5秒。本轮不改配置，未来部署以实际加载配置和启动/周期记录确认，不把名义频率当实测。

相机60 Hz周期约16.7 ms，与50 Hz消费并不要求一帧只被读一次。应检查持续输出、实际消费和总延迟，而非只看相机标称频率。

默认ray2d_timeout_ms=200。`common/abs_ray2d_shm_contract.h`定义时间戳为载荷完成时间；现有`ray_predictor.py`在推理后写入单调时钟。因此这是发布后的过期上限，不涵盖曝光、传输和此前推理耗时。未来实机发布器仍需明确采集到消费的总时龄；本轮不建设新接口。

匀速2 m/s时：16.7 ms前进3.3 cm，20 ms前进4 cm，200 ms前进40 cm。这些仅为运动学距离，不是制动距离、总响应时间或安全速度结论。不能用“60 Hz”单独证明2 m/s避障足够。

## 3. 误差实际进入网络的数值

假设同一束真实1 m、其他状态不变，仅列输入数学变化，不运行策略、不预测机器人行为：

| 射线距离(m) | 网络中的log2值 | 相对真实1 m的输入差 |
|---:|---:|---:|
| 0.8 | −0.321928 | −0.321928 |
| 1.0 | 0 | 0 |
| 1.2 | 0.263034 | 0.263034 |
| 2.0 | 1 | 1 |
| 6.0 | 2.584963 | 2.584963 |

log2保留比例差异；例如1→2 m与2→4 m都增加1。把未知填6 m会变成普通的远距离输入，不会被现有有限性校验识别为未知。近障高估必须单独检查，不能由总体MAE改善掩盖；低估也应记录，因为会影响绕障、推进与恢复占比。

## 4. 下一轮最小评价表

复用现有同帧双模型记录，不新增采集框架。每次静态场景记录：机身参考束方向、参考距离及测量误差、目标覆盖哪些束、原始深度、预处理方式、medium/epoch3输出、逐束有符号误差、绝对误差、近障高估、静止段输出范围/分位数、未知比例、实际输出频率和可获得的各段时延。没有独立标签或目标未覆盖的束只作响应观察，不评分。

优先覆盖正前方近/中/远平面及左右偏置近障；±45°画外交点单列，不与画内结果平均后宣称全部通过。原有离线“近障≤1.5 m”等分组定义可沿用，但它是分析分组，不是安全距离或通过阈值。

当前不制定没有依据的统一“5 cm合格线”，也不根据RA阈值反推米制误差许可。先回答：画内近障是否还会被预测成明显远距离、误差是否系统性、输入是否稳定及时。现有epoch3近障尾部高估及未完成低层安全准备，仍不允许接控制。静态评价后如需判断误差对RA/策略的作用，应另行限定离线状态样本或仿真比较；本轮不运行、不追加训练。
