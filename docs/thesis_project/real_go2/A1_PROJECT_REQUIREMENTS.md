# A1：基于 D435i 定位的 Go2 曲线路径到点控制

日期：2026-11-09
状态：需求与初步方案；尚未完成自动曲线到点和 5 cm 精度验证。
用途：三人协作项目的初始文档，可复制到后续独立仓库。本文不改变毕业设计总项目的唯一 ACTIVE 任务。

## 1. 要解决的问题

现有原生位置反馈与实际测量存在横向、纵向偏差，仅缩小软件到达容差不能保证实际到点精度。A1 使用 D435i 双目图像及其 IMU，经电脑计算获得定位和速度，支持机器人自动调整航向、沿合适路径从当前位置走到目标点。

A1 是毕业设计实机导航基础能力的独立工作，不替代风险驱动策略切换研究。

## 2. 已确定的要求

- 机器人为 Unitree Go2 EDU，任务仅在平地上进行。
- 以固定在机身上的坐标系和参考点为准，不使用全机器人重心作为导航参考点。
- 采用 D435i 定位方案，计算端可部署在外部电脑或机载计算单元；部署位置待实际链路和算力评估确定。
- 对外输出必须是机身参考点的位置、姿态和速度，不能直接把相机参考点当成机身参考点。
- 用户通过终端指定目标、查询状态、请求停止和退出。
- 自动规划航向及合适的平滑路径，正常跟踪以向前运动和转弯为主，不以侧向平移到点。
- 不强制每条路径弯曲：正前方目标可以走直线，需要改变方向时走合适曲线。
- 首期自动调整航向角；机身横滚、俯仰和腿部步态由原生运动控制处理。
- 目标实际水平到点误差不超过 5 cm；这是验收目标，尚非已有能力。
- 支持到达 B 点并停稳后，继续下达前往 C 点的命令。
- 定位运行不依赖地面定位标签或动捕系统。卷尺、地面测量标记和独立视频仅用于评价，不作为定位输入。

## 3. 坐标约定

### 3.1 固定机身坐标系

统一对外命名为 `base_link`：X 向前、Y 向左、Z 向上，绕 Z 轴左转为正。

参考点采用核对后的 Go2 模型机身 `base` / `trunk` 对应原点。具体模型、物理位置和两种命名的对应关系必须在实施时确认，不能仅凭名称视为同一点。

该坐标系固定在机身上，随机器人移动、转向，但不随腿部动作重新定义。它不等于机器人运动中变化的全身重心。相机定位转换、控制计算和实际测量均应使用这个参考点。

### 3.2 固定导航参考系

开始任务时，在机器人站稳且定位有效后建立局部导航参考系：原点取初始机身参考点的地面投影，X 轴沿初始机身前向的水平投影，Z 轴竖直向上。

该参考系建立后保持不动。到达 B 点、机头方向改变，不要求重建导航坐标系；系统通过当前位置及姿态，把目标换算为当前机身下的方向。

定位重新初始化、重置或参考系发生不连续变化后，不得沿用旧坐标目标继续运动；应停止任务，重新确认参考系和目标。

### 3.3 默认：按下令时的机体坐标指定目标

默认目标形式为相对位移 `(前向距离, 左向距离)`，单位 m。相对方向以接收命令时的机身朝向为准。

接收命令时，将相对目标转换成固定导航参考系中的一个固定点。运动期间不反复按新机头方向重算目标，防止目标随机器人移动。

示例：

1. A 点站稳，输入“前方 2 m、左侧 1 m”，确定 B 点。
2. 自动调整航向并跟踪路径，停在 B 点附近。
3. B 点停稳后输入“当前前方 1 m”，以 B 点此时的机头方向确定 C 点。
4. 前往 C 的过程中，C 点保持固定。

以上为语义示例，具体终端命令名称尚未确定。B 点到 C 点无需重置底层定位原点。

### 3.4 固定坐标目标

固定导航参考系中的绝对坐标目标可作为补充输入方式。界面必须明确区分“当前机体相对目标”和“固定导航坐标目标”，不得复用同一命令而隐含不同语义。

## 4. 定位与速度来源

候选链路：D435i 双目图像与自身 IMU → VINS → 相机 IMU 位姿与速度 → 安装变换及参考点转换 → 机身位姿与速度。

用户无需关心内部公式，但实现必须保证：

- 机身位置与速度对应同一个参考点，坐标系、单位和时间戳明确。
- 相机到机身安装外参应实际测量或标定，不根据照片猜测。
- 转弯时需处理相机与机身参考点间的旋转速度影响，不只修改位置。
- 相机与自身 IMU 外参、相机与 Go2 机身安装外参是两组不同变换。
- 定位失效、超时或明显跳变时停止运动任务，不静默切换到原生位置反馈继续走。

已有 VINS 结果仅支持继续只读验证。第 1 轮出现明确异常；第 2、3 轮位移量级接近人工测量，但共享初始化、测量近似且存在停后变化，不能宣称已达到 5 cm。原始异常记录保留，不因本轮先分析第 2、3 轮而删除或改写。

## 5. 路径与机器人执行

优先复用成熟的平滑路径生成与路径跟踪实现，再做必要的 Go2 适配，不从零开发通用导航框架。

候选方案：平滑路径生成 + Pure Pursuit / Nav2 Regulated Pure Pursuit 跟踪 + 终点接近和停车逻辑。具体软件集成方式待最小依赖评估后确定。

首期通过原生 `SportClient.Move(vx, 0, vyaw)` 执行前进和转弯，并使用 `StopMove` 请求停止；不接入低层 LowCmd，不释放原生运动服务，不启动毕业设计 RL 策略。

路径生成应考虑初始朝向、目标方向及可执行的曲率。若目标位于后方或不适合直接前进，可先受控转向，再向前跟踪，不强行生成过急曲线。

接近目标时须实际验证减速能力、指令延迟和停车距离。此前 0.30 m/s 能迈步只是已有现场线索，不能作为所有场景的最低速度，也不能直接用固定速度下限保证 5 cm 精度。

终点朝向可选；若用户未指定，不额外要求恢复起点朝向。朝向误差单独记录，不与位置 5 cm 指标混合。

本阶段限开阔无障碍区域，不声称具备自主避障。与毕业设计风险策略链的集成后续单独安排。

## 6. 停止与终端交互

终端至少提供：设置目标、查询状态、停止、退出。运动中应能接收停止，停止后不得因旧任务再次自动发出运动命令。

复用已有停止失败锁存与记录行为；运动控制只允许一个发送入口。原生遥控与电脑指令优先级尚不能视为已验证的独立急停保证。

`StopMove` 返回成功和程序退出均不等于物理停稳；现场须人工观察。电脑掉电、进程强杀和断网时不能保证清理回调执行，不进行未经安排的断线或故障试验。

## 7. 5 cm 验收定义

评价对象：指定机身参考点的实际地面投影。每次测量应使用相同物理基准或明确的测量换算方法，不用机头、脚尖等不同点交替测量。

位置误差定义为停稳后的水平欧氏距离：

`error = sqrt((实际X - 目标X)^2 + (实际Y - 目标Y)^2) ≤ 0.05 m`

不是 X、Y 各允许 5 cm，也不是控制器估计进入 5 cm 容差即验收通过。

测试需要独立测量目标位置及实际终点，测量不确定度应明显小于 5 cm。除终点误差外，记录停后位置变化、定位跳变、停止结果及失败情况。

首期在平坦开阔区域、短距离低速验证；具体距离、目标方向、重复次数、独立初始化安排及停稳评价时间窗，在正式验收前共同确定。三次探索测试不能直接证明所有条件下均达到 5 cm。

只有定位本身有足够准确度和稳定性后，才进入自动曲线到点实机验证；不能靠缩小容差、套用尺度系数或选择性删除失败记录制造通过。

## 8. 推进顺序与完成条件

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| 1：定位与接口 | 先审阅既有第 2、3 轮，开展受控只读测量，确认机身参考点与坐标接口 | 位置、速度、姿态及时间语义明确；误差、停后变化和异常如实报告，足以判断是否进入控制 |
| 2：路径与离线验证 | 复用平滑路径和跟踪算法，验证相对目标一次性转换、转向和连续任务 | A→B→C 目标含义正确，正常跟踪不依赖横移，停止后旧任务不恢复 |
| 3：低速实机闭环 | 从简单短路径开始，逐步检查转弯、终点接近和停车 | 能实际到达并停稳，异常可终止；无须依靠人工补走来宣称自动到达 |
| 4：精度评价 | 按固定测量方法重复测试，报告每次误差与失败 | 在明确的测试条件下评价是否满足 5 cm，不把探索结果泛化到任意环境 |

现场遇到异常速度、姿态、线缆风险、定位失效或停止失败，应结束该项运动验证并保存记录。具体现场动作由主助手与现场操作者安排，执行器默认负责离线工作。

## 9. 三人分工

| 分工 | 主要交付 |
|---|---|
| 定位与坐标 | D435i/VINS 接入、机身安装外参、统一机身里程计接口及定位误差分析 |
| 路径与跟踪 | 成熟算法选型与复用、平滑路径、航向跟踪、终点接近与离线验证 |
| Go2接口与实验 | 原生 SDK 适配、终端交互、停止和记录、独立测量与现场实验整理 |

先共同确定接口，再分工实现。原始数据、失败结果和关键配置保留；每次运行后关闭并核对本次进程，避免影响他人会话。

## 10. 仓库与总项目关系

计划新建独立仓库，由用户后续确定目录、名称及 GitHub 设置，本轮未创建。

优先与毕业设计总仓库并列放置；未来如需嵌入总项目，采用正式 Git submodule，避免直接在已跟踪子目录中随意嵌套 `git init`。

仅复用 A1 必需的 VINS 补丁、配置、SDK 适配及记录工具，核对许可证并记录来源版本；迁入后确定唯一维护位置，避免两份代码分别修改。通过明确接口向毕业设计提供机身定位、速度及导航功能，不复制整个总项目，也不修改仿真历史。

日常按分工使用分支和 PR；大型原始 bag、视频和构建产物不放入普通 Git 历史。总项目集成时记录所使用的 A1 版本。
