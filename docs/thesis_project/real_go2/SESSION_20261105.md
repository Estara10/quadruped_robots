## D435i与VINS路线

- 用户决定使用D435i，同时服务于后续障碍感知和独立里程计。原ABS公开Go1实机代码使用ZED mini＋ZED SDK视觉惯性跟踪；VINS是同类替代，不能称为相同内部算法。Go1代码继续作为主要参考，Go2接口差异单独确认。
- 当前相机直连链路5000Mb/s。Ubuntu22.04.5、Humble；用户安装RealSense SDK2.58.4、ROS驱动4.58.4及对应官方udev规则。相机固件5.13.0.55。图像、独立gyro/accel与合并IMU均已有直接接收证据。
- 首次六路采集被IMU IIO权限拒绝，随后报告设备断开；两者因果未确认。规则安装并重新插拔后启动成功。图像代表帧有效深度由约19%变为约66%，只说明本次场景有效区域改善，不是深度精度验证。
- SDK提示IMU Calibration is not available，使用默认参数；候选IMU噪声/外参不能当成本机已标定。投射散斑是否适合运动跟踪仍待确认。
- 已完成VINS候选CPU/Humble隔离构建：上游zinuok/VINS-Fusion-ROS2提交72023bc5d2abb14faa4c02a5c040d84f996b587a，Ceres2.0、OpenCV4.5.4、APT Eigen3.4。保留虚拟归一化FOCAL_LENGTH=460，真实相机内参在左右YAML。配置与最终补丁保存在[scripts/go2_vins](../../../scripts/go2_vins/)。临时源码和二进制位于/tmp，不随Git备份，重启后可能需要重建。
- 补丁后Odometry的twist为相机IMU body系，参考点仍是相机IMU原点；不得再重复VINS世界系到该body的旋转，但转为Go2基座速度仍需安装外参和杠杆臂转换。没有接入控制器。

## 首次VINS静止现场检查

相机-only、ROS域42、左右红外640×480@15Hz，合并IMU约200Hz，深度/RGB关闭，投射器默认；用户收到保持相机静止的指令。

1. 主助手首次复制运行配置时改用绝对标定路径，而该移植无条件拼接配置目录，产生错误路径并导致启动崩溃（-11）。保留失败记录；随后保留相对文件名并复制左右标定文件，未改算法参数，重做同一检查。
2. 修正后运行35秒，约2.5秒内部初始化完成；左右各510帧全部有相同header时间配对，约15Hz，合并IMU约199.98Hz。此结果不等于独立证明完全硬件同步。
3. 优化Odometry约7.43Hz，最大接收间隔495ms；传播输出约199.93Hz。第5秒后，优化速度模均值0.00270m/s、最大0.01507m/s，位置相对段首最大变化0.00141m；传播速度模均值0.00588m/s、最大0.02675m/s。无独立精密静止真值，不称为精度标定。
4. 特征图可见部分特征落在投射散斑及反光区域；静止初始化不证明动态跟踪、尺度、方向、外参或时间偏差已验证。
5. VINS收到SIGINT后报`terminate called without an active exception`，退出-6；相机正常退出0。两者均已核对无残留，不把本次全流程称为通过。

结果入口：[35秒检查报告](../../../logs/real_go2/20261105_155923_d435i_vins_static_path_corrected/RESULT.md)。用户可单独运行`source /opt/ros/humble/setup.bash`后执行`realsense-viewer`观看；是否由用户启动、关闭该窗口未确认，不冒称已经关闭用户手动会话。
