## 步骤 1：确认 RA 方向与现有时间事实

核对部署控制器的 RA 比较、RA 输出进入切换器的路径，以及直接相关的 ABS 参考或部署定义。有现成运行记录或受控输入证据时一并核对。区分“现有代码怎样比较”和“RA 数值实际上表示什么”；不能只凭变量名或现有比较符判定风险方向。

## 步骤 2：制定四组正交状态转移合同

以确认的 RA 方向为前提，定义 A/B/C/D 的进入和退出比较符，以及 RA 恰好等于进入、退出或单阈值时的行为。状态转移表覆盖当前模式、RA 条件、hold 启用和到期情况、下一模式、本周期动作来源、计时处理及转移原因。

必须满足：

- A/B/C/D 使用同一进入阈值及比较符；A/C 使用同一单阈值退出条件；B/D 使用同一退出阈值及比较符。
- A/B 不保持；C/D 使用相同保持时长及计时规则。保持不得改变进入条件。
- 四组使用相同 Agile、RA、Recovery 模型和 observation、action、缩放、限幅、控制链、Recovery 命令写入方式。
- 除滞回和保持外无第三个组间研究变量。现有候选若有不同进入比较符、隐藏退出阈值、动作缓存或 Recovery 优化行为，列为合同差异，不悄悄沿用。

明确新 run 的初始模式、首个有效 RA 前的行为、会话重启时的模式和计时器重置、终止事件后的切换处理。正式 run 不热更新组别、阈值和 hold 参数。说明已在 Recovery 时再次满足进入条件是否重启保持，以及 hold 到期当周期能否退出。

**交付并停止：**完整转移表、边界与生命周期规则、四组不变量、与候选实现的已知差异。不改运行时算法。提交 Director 审阅。

## 步骤 3：冻结 hold 与配置语义

研究合同优先以真实时间表达最小保持，如 `recovery_min_hold_s`。明确起算事件、使用的时钟、到期比较、到期周期的退出行为，以及 policy 延迟或漏周期的时间解释。对负时间、时间回退和非有限时间值给出足以保证仿真结果可解释的最小处理，不建设工业级故障恢复。

确定组别、进入阈值、退出阈值和保持时间的唯一配置来源。**不要同时让组别 ID 与两个独立启用布尔值都作为可填写的权威；**启用因素由组别唯一推导。定义如何发现负保持时间、非有限或缺失阈值、与 RA 方向矛盾的阈值顺序及组别参数冲突。跨组参数相等属于正式实验配置约束：本步写明约束，后续冻结配置时核查，不建设复杂 schema。

若实际频率仍无可信证据，保持 `UNKNOWN` 并给出后续 S1 实测方法；合同不得依赖猜测的 50 Hz 或 125 Hz。

**交付并停止：**字段与单位、合法性规则、hold 时间与异常语义、频率证据和剩余 UNKNOWN。提交 Director 审阅。

## 步骤 4：定义事件、周期对应关系和候选实现映射

定义事件及所属策略周期：

1. `risk_condition_met`：进入条件在本周期成立；另行定义本次**首次进入风险条件区间**的时刻，避免持续高风险时每周期重复算触发，并说明响应延迟使用哪个时刻。
2. `policy_mode_changed`：状态机在本周期进入 Recovery 或返回 Agile。
3. `recovery_command_issued`：首个 Recovery 路径生成的命令写入控制输出。
4. `recovery_command_applied`：仅在可可靠确认 MuJoCo 消费命令时使用；命令写出不等于已执行。

说明现有记录中 RA、切换前后模式和动作是否同属一个策略周期，以及会话、单调周期号、单调时间戳、阈值、hold 状态、动作来源和转移原因需要怎样关联。本步只定义语义和记录需求，**不要求改造运行时日志**。无法从现有记录证明的事件标为 UNKNOWN，指出后续 S1 的最小补足位置。

对照 `paper_faithful_switch` 和 `stabilized_switch`，说明哪些行为符合合同、哪些只是 A/D 类候选、哪些不能直接沿用。不以 legacy PASS 代替当前判断。

**交付并停止：**事件与周期定义、现有记录的可判断范围、待补的最小记录需求、候选实现映射。提交 Director 审阅。

## 步骤 5：少量手工序列核验与定稿

用可读的离线 RA 序列推演四组，覆盖低于/等于/高于进入阈值、等于/越过退出阈值、阈值附近往返、hold 未到期风险下降、到期周期可退出或风险仍高、Recovery 中再次满足进入条件，以及 NaN、正负无穷和异常时间。相近边界可合并，不建设大型测试框架。

关键周期展示 RA、原模式、hold 状态、新模式、转移原因和预期动作来源。确认四组只因滞回和保持产生差异，事件可关联到相应周期。不运行正式 MuJoCo 场景。

整合最终技术合同：RA 证据、转移表、配置、hold 与异常语义、事件与周期、手工结果、候选映射、Remaining UNKNOWN、下一任务所需接口边界。在本任务文件中引用合同位置，提交最终 `S1-01 Execution Report`。最终审查通过前不把任务标为完成，也不进入 S1 后续任务。

**交付并停止：**最终合同、推演结果与报告，提交本次轻量独立审查。
