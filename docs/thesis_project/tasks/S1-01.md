# S1-01：统一 A/B/C/D 切换合同与时间语义

## 目标

在修改切换算法前，确定四组唯一、正交且可实现的状态机语义，为后续 A、B、C、D 分步实现提供同一接口。

## 需要决定

1. A/B/C/D 的进入和退出条件；
2. RA 等于阈值时的行为；
3. 滞回使用的进入/退出阈值字段；
4. 最小保持只作用于 Recovery，并以秒还是策略步表达；
5. policy 实际频率如何测量和记录；
6. NaN/Inf、时间异常等少量必要异常行为；
7. 如何从运行记录判断 RA 越阈、模式改变和 Recovery 动作生效。

## 本任务不做

- 不实现 B/C/D；
- 不正式跑场景实验；
- 不训练模型；
- 不处理旧 P1 Reviewer Minimum Fix Set；
- 不补历史 hash、manifest 或 evidence；
- 不进行实机测试。

## 最小验证

- 用少量手工 RA 序列覆盖低于、等于、高于阈值和阈值附近往返；
- 推演 A/B/C/D 的预期模式序列；
- 用当前控制频率核算保持时长，确认不会把 50 Hz 当作 125 Hz；
- 确认四组之间只存在滞回和保持两个研究因素。

## 完成条件

- 形成一张无歧义的四组状态转移表；
- 配置字段名称和单位确定；
- 时间与三个关键事件定义确定；
- 下一任务可以直接按合同实现或校准基础控制链。

## 状态

`ACTIVE`。
