# S1-02：关键接口与基础仿真时基核对

## 状态与目标

`COMPLETE`（Director 有条件通过）。S1-01 的 A/B/C/D 切换合同已经通过审阅。本任务核实当前 Go2 仿真控制链能否可信地承载该合同：三模型接口与动作链是否一致，policy/RA 实际以什么频率运行，现有记录能否重建一次基础 Agile→Recovery→Agile 过程，以及 MuJoCo 仿真时间到控制器的缺口在哪里。

Director 审阅结论：S1-02 有条件通过，可标记 COMPLETE。Agile 和 Recovery 部署模型的真实 12 维动作关节顺序仍为 UNKNOWN；该接口风险必须在正式实验前讨论，不得表述为已经验证。此结论不授权启动 S1-03 或其他后续任务。

本任务只建立**基础运行事实**。不实现正式 A/B/C/D 配置与新切换算法，不冻结实验阈值，不做场景或参数比较。

## 执行与审阅方式

执行 Agent 可以连续完成本任务的内部步骤，**完成整个任务后提交一次报告供 Director 审阅**，不必每做一小步就停下。遇到使基础运行不可信、阻止下一步、明显实机风险或与已通过合同冲突的事实时，停止受影响的工作并报告具体证据；不为关闭历史 UNKNOWN 扩张任务。审阅通过前不启动下一任务。

开始前阅读 `AGENTS.md`、`CLAUDE.md`、`OVERVIEW.md`、`ROADMAP.md`、`CURRENT_STATE.md`、`EXPERIMENT_PLAN.md`、已完成的 `tasks/S1-01.md` 和 `SWITCH_CONTRACT.md`。技术检查只读直接相关模型、配置、控制器、MuJoCo 时钟和记录代码，不扫描整个仓库。原 ABS 论文及作者代码只在接口定义有疑义时作为原始参考；当前部署行为仍以本仓库直接证据为准。

## 工作 1：核对关键模型与动作接口

建立一张简洁的“模型输入 → 模型输出 → 控制器使用”对照表，至少包含：

- Agile、RA、Recovery 的实际输入输出维度与本地部署模型的一致性；
- observation 各段顺序、joint/action 顺序、关节目标与动作缩放/限幅；
- RA 输入的 base twist、相对目标和 ray2d 的顺序与单位；
- Recovery 的安全 twist 输入、策略动作、关节目标到控制接口的路径；
- 影响结果的频率与时间字段来自配置、代码推导还是运行测量。

只验证会改变动作或论文结论的接口。发现不一致时记录“期望、实际、影响和最小修复位置”，不要暗中修改算法或模型。已有证据足够时直接引用，不恢复历史训练环境或模型来源链。

## 工作 2：核对时钟与记录链

- 查明 MuJoCo `sim_time` 的发布位置、样本有效性和 run/session 边界；确认当前控制器是否消费它。若尚未接入，只确定后续最小接入点，不在本任务实现 C/D 的 hold。
- 查明当前 runtime frame、recorder 与控制接口日志的时间基准、`session_id`、`rl_step`、RA、模式、动作来源及记录频率。区分同一策略周期、控制器写命令周期和 MuJoCo 消费命令。
- 明确现有证据能证明哪些 S1-01 事件，哪些仍为 UNKNOWN。特别是命令写出不得称为 MuJoCo 已执行。

允许仅为取得必要的基础运行证据做**最小观测性修正**，但不得改变策略输入、状态转移、动作值、模型或控制频率。若补记录需要较大改动，给出下一任务所需字段和位置，本任务不建新日志框架。

## 工作 3：一次短时基础仿真诊断

使用现有 Go2/MuJoCo/ROS 2 链和明确记录的当前切换候选，完成最少量的诊断运行。优先使用 `paper_faithful_switch` 观察单阈值基础路径；它只是 A 类候选，不能写作正式 A 组结果。可用简单静态障碍或受控诊断输入触发一次风险和恢复，但必须写明所用场景、配置及任何临时覆盖。以能判断基础链为止，不重复刷场景或调参。

从**当前这次运行**而非注释或历史捕获中，计算连续策略步的实际周期/频率，并核对 RA 是否每策略步更新。记录 RA、模式、动作和必要的机器人状态，尽量观察 Agile→Recovery→Agile；只声称记录能够证明的事件。若当前环境无法启动或无法可靠触发，记录最小复现步骤、具体失败和下一步所需条件，停止诊断，不把历史数据当作本次实测。

本次诊断不是正式实验：不纳入论文统计，不冻结 A/B/C/D 参数、重复次数或场景，也不运行训练或实机。

## 最小完成条件

- 三模型与控制链的关键维度、顺序、单位和动作映射有直接证据；影响输出的冲突已明确标出。
- 当前运行的 policy/RA 频率有测量值，或有可复现的具体阻塞；不得以 50 Hz/125 Hz 配置或旧注释代替实测。
- 能用一次基础诊断的记录解释 RA、模式和动作在同一策略周期的关系；若未观察到完整进入与退出，明确缺失原因，不声称闭环已验证。
- MuJoCo `sim_time` 到控制器及记录链的现状和最小接入边界清楚；未把 S1-01 合同写成已实现的 hold 行为。
- 没有运行正式实验、训练或实机测试，也没有提前实现 B/C/D。

若前两项或基础运行的可信性因具体故障而无法完成，状态应报 `BLOCKED` 或 `INCOMPLETE`，而不是为了提交报告将 UNKNOWN 当作通过。S1 阶段是否完成须在后续基础闭环与时间语义实际核验后判断。
