# S1-03：仿真时钟接入与切换事件记录

## 状态与目标

`COMPLETE`（2026-10-08 Director 有条件通过）。正常连续运行的时钟、策略事件与命令来源已有运行证据；暂停后策略恢复及同名共享时钟重连仍未验证。当前支持边界为正常连续运行，暂停或安全中止后的 run 不直接续接，恢复流程另行安排。

S1-01 切换合同已通过；S1-02 已有条件通过，取得约 50 Hz 的连续策略记录及 MuJoCo 时钟配对证据。本任务让控制器读取并记录仿真时间，直接关联风险判断、模式转换和 Recovery 命令写出，为后续保持时间和响应延迟验证提供基础。

## 工作一：接入并记录 MuJoCo 时间

复用已有 MuJoCo 时钟发布链，选择最小接入点，明确：

- 时间字段和秒单位；
- 样本来源、序号或等价标识，以及 run/session 或时钟段边界；
- 样本有效性、旧样本隔离和首个有效样本前的状态；
- 暂停、恢复、仿真重启、时间回退或重置的处理；
- 如何区分仿真时间不增长与时钟来源失效；无法可靠区分时明确记录 UNKNOWN。

每个策略周期记录实际使用的 `sim_time` 样本、有效状态和必要的来源/年龄信息。异步获取的最近样本不得称为策略决策瞬间的精确仿真时间；说明关联误差或保留区间。

本轮时间状态用于观测和后续接口，不改变当前候选的切换条件、保持计数或动作。后续时间保持如何消费有效时钟留给相应任务，不在本轮扩张为故障恢复系统。

## 工作二：补齐策略周期和事件关联

复用现有 runtime frame、遥测和记录器，避免新建通用日志框架。每个策略周期至少可关联：

- `session_id`；
- `policy_cycle_id` / `rl_step`；
- 单调时间戳及仿真时钟样本信息；
- `mode_before`、`mode_after`；
- RA、实际阈值和当前切换候选；
- 动作来源及转移原因。

按已通过的 `SWITCH_CONTRACT.md` 定义和记录：

| 事件 | 本轮要求 |
|---|---|
| `risk_condition_met` | 本周期有效 RA 满足进入条件；它是周期条件，不能误作新的风险边沿。 |
| `risk_condition_entered` | 连续有效周期内条件由假变真；首帧或缺口不推造精确边沿。 |
| `policy_mode_changed` | 锚定状态机完成转换决定的位置，记录前后模式、原因和来源周期。 |
| `recovery_command_issued` | 每次 Recovery episode 中，首个 Recovery 来源命令实际写入控制接口时记录；携带其来源策略周期。 |
| `recovery_command_applied` | 只有能可靠确认 MuJoCo 消费同一命令才记录；本轮不强制增加消费确认。 |

控制接口的重复命令写出也应能够直接关联来源策略周期与动作来源。不能仅凭时间接近和四位小数目标匹配确定来源。跨周期或跨线程传递时保持动作和来源元数据一致，不修改动作数值。

Recovery 中再次出现风险边沿只记录风险事件，不配成新的 Agile→Recovery 进入响应。首帧风险成立、周期缺失或时间无效时，按合同保留 UNKNOWN 或区间。模式、动作生成、命令写出及仿真消费是不同位置的事件，不混用时间戳。

若必须修改共享帧格式，同步更新直接生产/消费它的组件，明确版本与兼容范围，使旧格式不会被静默错读；不扩张为全面迁移旧工具。

## 工作三：最小验证

完成直接受影响组件的编译和有针对性的离线检查后，进行最少量的非正式仿真诊断。验证：

1. 正常运行中，策略周期有可解释的仿真时钟样本关联；
2. 暂停、恢复及重新启动时，时间与时钟段的记录符合定义，旧样本不会被当作新 run 的有效时间；
3. 一次 Agile→Recovery→Agile 的风险条件、模式变化与动作来源可按周期解释；
4. Recovery 首次命令写出能直接对应来源策略周期，重复写出也有来源；
5. 当前切换候选的进入、退出条件和动作链未因观测改动而改变。

优先使用 `paper_faithful_switch` 候选；记录场景、实际配置、模型路径和临时覆盖。这是基础诊断，不是正式 A 组结果。暂停/重启检查可按必要的最短过程完成，不做场景比较或参数扫描。

测试应针对时间生命周期、边沿和元数据关联等容易出错的语义，不为简单记录赋值建设庞大测试框架。无法触发或出现安全 veto 时保留已有记录，报告具体缺口，不重复刷场景或猜测补齐。

## 允许与禁止范围

允许修改直接相关的时钟接入、事件观测、来源元数据、记录器及当前任务文档，允许必要的构建、离线验证和短时诊断仿真。

禁止：

- 修改模型、观测数值、动作值、控制频率或现有切换条件；
- 实现正式 B/C/D、修改保持计数语义或冻结研究参数；
- 训练、重新导出模型、正式实验或实机测试；
- 恢复历史训练环境、追查 artifact 历史关节顺序；
- 继续旧 P1、Gate、Reviewer 或 exec-plan；
- 提交 Git 或自动启动后续任务。

## 最小完成条件

- 控制器能取得 MuJoCo 时间，记录来源、有效性、年龄/关联误差与生命周期语义；
- 策略记录明确包含同周期 RA、前后模式、动作来源和转移原因；
- 模式转换与 Recovery 首次接口写出分别有事件位置、时间和来源周期；
- 暂停、恢复和重启有最小验证证据；不能证实的内容如实保留；
- 原有切换和动作行为没有被观测修改改变，直接受影响组件可构建和运行；
- 未将命令写出说成 MuJoCo 消费，未提前实现时间保持或正式组别。

解决不了的问题记录影响和下一步最小办法，不为清空 UNKNOWN 扩张任务。若关键周期或时间关联仍不可信，报告 INCOMPLETE 或 BLOCKED。
