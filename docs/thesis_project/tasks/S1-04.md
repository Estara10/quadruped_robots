## 工作一：单次 run 的起点和终点

先核对已有实现，再做必要的最小补足，形成简洁的 run 合同：

- 每次运行有唯一 `run_id`、证据目录及明确关联的 controller `session_id`；启动准备和站立时间与实际运动时间区分；
- 记录场景、目标、初态、候选、阈值、模型路径及诊断配置；核对目标、机器人位姿和距离的坐标系与单位；
- 定义运动开始事件和仿真时间，首个无效时钟不能被当作精确起点；需要时保留区间或 UNKNOWN；
- 明确到达、碰撞终止、跌倒、仿真时间超时、人工中止、系统安全中止和启动失败的判据、证据来源及优先级；
- 正常地面接触不得算障碍碰撞；碰撞发生记录与“是否终止”是不同概念，诊断采用的规则须写清；
- 终止只产生一份最终结果，保留触发原因与时间。未观察到终局、记录中断或进程被杀不能默认为成功；
- 终止后停止策略输出、保存记录并清理本次启动的进程；清理结束与运动结束分别记录。进程停止时刻不清楚时不得凭清理检查反推；
- 墙钟硬时限用于防止诊断悬挂，到期记中止/不完整；不能冒充按仿真时间定义的任务超时。

S1-03 已证实全局安全停止可能不出现在最后一帧的 `safety_faulted` 中。须接通当前实际安全终止来源，使日志中的冻结位置检测/PASSIVE 能进入 run 结果，不能仅依赖策略帧布尔值。无需建设全面故障分类系统。

本轮 run 不暂停、不热重置或续接安全中止的 session。保留已有安全机制；发生安全中止就结束该 run，后续重新启动形成新 run。

## 工作二：基础指标和记录完整性

从实际周期/事件记录计算至少以下结果，并说明方法、时间基准和无效数据处理：

| 内容 | 最小要求 |
|---|---|
| 终局 | 成功、碰撞终止、跌倒、超时、人工/系统中止、启动失败或不完整；同时保留其他已观测事件 |
| 运行时间 | 运动起止的仿真秒；墙钟耗时另列，不互相替代 |
| 切换 | 进入次数、退出次数、总转换次数及相邻转换间隔 |
| Recovery | 单次驻留区间、累计驻留时间及在有效运动时间中的占比；尾段或时钟缺失不得编造精确时长 |
| 短时反向切换 | 明确统计定义及窗口 W；W 是本次诊断值，不是正式冻结值 |
| 任务运动 | 目标距离、位姿/速度记录，以及按明确方法计算的基础平均速度 |
| 周期质量 | 策略帧数、周期缺口、实际周期分布、时钟无效样本和事件关联缺口 |

跨 session、缺帧或无效仿真时间时，保留 UNKNOWN/区间和覆盖范围；不插值生成不存在的转换。不要把每帧风险条件成立算成新事件。

进入风险到模式变化/命令写出的关联优先复用 S1-03；缺少可靠事件仿真时间时只能给出已支持的时间基准或 UNKNOWN，不能把单调墙钟延迟改名为仿真延迟。MuJoCo 命令实际消费继续 UNKNOWN，不是本任务必做项。

不要求为每个终局另外跑完整仿真；可用直接来源核对和离线样例覆盖未出现的分支。未验证的检测器必须明确记录，不能只因有结果字段便称已验证。
