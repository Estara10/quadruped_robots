# S2-01 — A 组单阈值实现与功能基线核验

**状态：COMPLETE — Director 有条件通过（2026-10-10）。**

## 目标

在已通过的 [切换合同](../SWITCH_CONTRACT.md) 下实现并核验 A 组原始单阈值行为，随后最多进行两次必要的非正式短诊断，建立真实 RA 驱动的功能基线。此草案不等同于正式实验授权。

## 进入条件

- S1-06 已有条件通过；但首次运动诊断前必须补齐足接触来源核验（见下文）。
- 核对工作区实际加载的 controller 配置、模型路径、运行候选及来源，避免 overlay/package-share 与 launch 配置不一致。
- 运动前发现足接触具名来源缺失或明确错位时，停止受影响的运动诊断并报告；不自动改映射。

## 工作范围

### 1. A 组实现与配置核验

- 按合同实现明确的 A 配置：`RA >= E` 时从 Agile 进入 Recovery；处于 Recovery 时 `RA < E` 退出。
- 不启用滞回、最小保持时间或其他切换条件。
- 核对配置实际消费、新旧配置冲突、运行来源及阈值记录；不能仅凭 YAML 存在或 shell 中的包路径推定运行时已加载。
- 保持 Agile、RA、Recovery 模型，观测/动作构造、关节处理和 Recovery 命令路径一致；本任务不重新设计这些接口。

### 2. 实际生产路径功能检查

调用实际切换生产路径，针对性检查：

- `RA == E`、`RA < E`、`RA > E` 的进入和退出边界；
- 初始化状态、模式重置和重新进入状态；
- 非有限/缺失输入及其他合同规定的无效输入处理；
- A 不保留滞回阈值或 Recovery hold 的配置互斥规则。

**离线功能检查与仿真证据分开：**离线状态机检查可以向实际生产切换函数传入手工 RA 序列，核对阈值边界、初始化/重置和无效输入；这只验证函数行为，不是 RA 模型输出或仿真证据。实际仿真必须使用部署 RA 模型自然产生的输出，禁止替换、注入或改写模型输出来制造切换。任何阶段都不得降低或关闭安全检查。

### 3. 首次运动诊断前的足接触来源核验

首次诊断先做源码来源核对，再在同一次运行的 PASSIVE／固定站立准备阶段读取 controller 实际收到的四个 loaned state interface 名称及顺序。准备阶段不进入 RL、不计为额外运行次数，也不关闭安全检查。只有实际名称与来源链、生产转换一致才允许转入 RL。

逐段确认并保留具名证据：

1. MuJoCo 中各具名足传感器到 SDK `foot_force` 数组索引；
2. 数组索引到具名 ROS state interface 的发布绑定；
3. controller 在上述准备阶段实际收到的四个 loaned state interface 名称及顺序；
4. controller 接触向量变换到策略 `FL, FR, RL, RR` 的结果。

不根据未经证明的接口数组顺序推定语义，不依据步态猜测，不尝试交换排列来观察行为。若来源不明或发现明确错位，不进入 RL；保存证据、清理本次准备环境并停止受影响部分，交 Director 决定修正。实机 SDK 的物理传感器语义留给 S9，不在本任务扩展。

### 4. 最多两次非正式短诊断

仅在 A 功能检查、来源/配置预检和足接触来源核验通过后进行。开始前选择并记录能回答切换功能问题的代表场景、目标和诊断上限；选择应避免复用此前很快到达、未触发 Recovery 的极短目标任务。参数在运行前记录，运行中不热更新。最多两次，每次使用独立 run/session，且仅为回答必要功能问题。

- 通过真实 RA 自然触发时记录 Agile→Recovery→Agile；不要求必然发生转换。
- 记录阈值/candidate/来源、策略周期、RA、模式、动作来源、Recovery episode/命令写出、驻留区间、安全事件、任务终局和时间线。
- 命令写出不等同于 MuJoCo 消费或动作已生效；终局和安全事件按当前合同解释。
- 如果未触发切换，如实报告功能证据缺口，不人为改变 RA、不替换 RA 模型输出、不调整研究阈值、不关闭安全检查；不超过两次，不为获得切换反复试跑。
- 出现安全 veto、配置不符、来源混流、足接触错位或记录无效时停止该次运行；不得为追求成功而超过两次上限。

### 5. 清理与报告

每次运行后只关闭本任务启动或确认属于本任务的仿真、controller、ROS launch、RViz、recorder 及辅助进程；核对退出，不影响无关会话。保存原始记录，区分直接观测、代码推断和 UNKNOWN。
