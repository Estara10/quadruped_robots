在 MuJoCo 仿真窗口左上角加入容易阅读的文字面板，让用户看到机器人当前速度、策略和风险状态。复用现有运行数据与渲染能力，只读显示，不改变控制行为。保留现有独立终端显示工具作为备用。本任务不验证或宣称 A 的避障性能已达到原论文。

连续完成整个任务后一次提交 Director 审阅，不需每个内部步骤停下。

## 显示内容

优先使用现有 MuJoCo 文字叠加接口，在左上角清晰显示以下内容；避免覆盖已有菜单、警告和性能信息。若中文字体不可用，使用简短英文标签并在报告中解释，不新增字体或 UI 框架。

| 项目 | 含义与来源要求 |
|---|---|
| 当前水平速度（m/s） | 机器人实际水平速度大小，不是目标速度或仿真播放倍率；明确使用的参考系与计算方法 |
| 策略模式 | Agile / Recovery；未进入 RL 时不得默认显示 Agile；FAULTED、无数据及过期数据分别提示 |
| RA 与阈值 | 本周期风险值和实际进入/退出阈值；不能使用写死数值冒充实际配置 |
| 距目标距离（m） | 实际机器人世界位置到本次已确认目标的水平距离；没有可靠目标来源时显示 N/A |
| 仿真时间（s） | 使用 MuJoCo 仿真秒，并明确标为 Sim time；若显示运行经过时间，必须注明起点，不能把墙钟或启动准备时间称为任务耗时 |
| 数据状态 | LIVE / STALE / MISSING / INVALID，以及简洁的数据年龄提示；停止后不能继续呈现旧帧为实时值 |

只展示必要数字，速度和距离保留两位小数即可。可以保留启动阶段文字提示，不展示大段关节数组。无需曲线、按钮、仪表盘或复杂交互。

## 数据与接入要求

- 策略、RA 等优先复用 controller 发布的实时帧；使用现有一致性、来源、版本及新鲜度规则，不能在显示层伪造或补零。
- 如速度/位置使用 MuJoCo 原生数据、而策略信息使用 controller 帧，说明不同来源与时间关系；不声称所有量精确同周期。
- 目标信息优先复用已有运行来源。若需新增字段或最小只读接口，先检查是否可避免；确有必要时同步生产者与读取器的布局/版本，不能只改一端。
- 控制器退出、数据过期、共享对象残留或新 session 出现时，清空旧策略/RA 显示并重新核对来源。无有效数据时显示状态或 N/A。
- 面板只读取数据，不发送命令，不影响模式、动作、阈值、控制频率、安全检查或 Recovery 优化。
- 在渲染线程进行显示；避免等待控制器、阻塞共享数据读取或在物理/控制循环中增加绘图工作。使用既有线程/锁约定，不引入新的后台服务。
- 保留终端 HUD 入口；不为此次面板改造整套记录或报告系统。

## 最小核验与运行边界

只核对直接受影响的数据转换、状态判断和渲染路径，完成必要增量构建。针对合法帧、无帧、过期、无效与来源变化，使用既有离线样例或少量针对性检查；不能把模拟帧展示当作实际运行证据。

允许一次必要短仿真查看实际窗口，沿用当前 A 配置、已有模型与诊断设置。运行前记录设置，完成显示/GLFW 和来源预检；不参数扫描、不修改 RA 以制造 Recovery、不关闭安全检查。可以复用新 A 配置消费证据，但不得因面板正常就宣布避障性能通过。

保存真实窗口截图，说明各显示值的来源和核对依据。若真实运行未出现 Recovery，以离线状态显示核对覆盖该标签，不能声称已观察到 Recovery。检查 controller 停止后旧帧不再被显示为 LIVE；必要时在正常收尾观察窗口，不为此追加运动运行。

显示预检失败时不启动场景；运行或关键记录失败时停止受影响部分并报告，不自动追加第二次场景运行。此前已授权的沙箱外桌面/OpenGL 与当前仿真诊断范围可按需使用，不修改系统授权、驱动、安装组件或全局环境。
