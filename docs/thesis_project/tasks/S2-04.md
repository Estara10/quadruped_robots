## 用户入口与本轮场景

给 `scripts/s1_run_diagnostic.py` 增加 `--scene` 参数；默认 `scene_obstacle.xml`，旧命令仍能运行。先支持以下五个已有文件：

| 文件 | 显示名称 | 静态障碍数量（当前 XML） |
|---|---|---:|
| scene_obstacle.xml | 原固定障碍 | 7 |
| scene_flat.xml | 平地 | 0 |
| scene_ppt_sparse.xml | 稀疏候选 | 4 |
| scene_ppt_medium.xml | 中等候选 | 7 |
| scene_ppt_dense.xml | 密集候选 | 11 |

文件均位于 `unitree_mujoco/unitree_robots/go2/`。本轮采用明确支持列表，不支持任意外部 XML、坡地、动态障碍或随机生成。未支持、缺失和无法解析的场景须在启动 RL 前明确拒绝，不静默退回默认。

目标和 A 配置规则沿用当前入口；`--goal-x` 仍须与实际部署配置一致，目标 Y=0。不要顺带扩建目标配置系统。最终给用户提供可以复制的平地、稀疏、中等、密集命令及记录分析命令，并说明当前目标 (7,0)、0.5 m 到达范围及结束条件。

## 关键实现要求

### 1. 同一个场景贯穿运行链

当前 `s1_run_diagnostic.py` 将场景、scenario ID、模型 fingerprint 等绑定到 obstacle_test1；`obstacle_collision_authority.h` 也只识别七个固定几何签名。必须同步解除这两个层面的固定场景限制，不仅替换启动参数。

使用一处轻量场景定义/解析入口提供实际选择的文件、ID、障碍集合和必要运行身份，避免 Python/C++ 维护互不一致的名单。可以复用编译模型和既有绑定接口；不建设通用场景框架、复杂 manifest 或新的治理目录。

实际加载模型、ray2d 来源和碰撞快照必须对应选择的场景。在预检/运行来源日志和 run_context 保存所选场景、实际路径、ID及障碍数量。身份不一致时拒绝 RL 或将记录明确判无效。仅保留防止混流/错场景所需的现有绑定，不额外追查历史来源。

### 2. 正确区分障碍与地面

- PPT 场景使用已有 `ppt_obstacle_*` 具名几何体；原固定场景的无名障碍必须保持可准确识别，不能仅凭某个固定 geom ID。
- 排除 floor、机器人 visual/collision geoms、灯光和其他非障碍资产。不能把所有 worldbody 几何体一律算障碍。
- 平地的空障碍集合是合法情况，不得因没有七个障碍而 INVALID，也不得因此把足—地面接触算成障碍碰撞。
- 未能可靠分类的接触保留 UNKNOWN，不能忽略后输出“无碰撞”。
- 保留物理步累计、历史覆盖、跌倒规则、诊断终局优先级和运动窗口边界；不改变“机器人—障碍 contact 触发终局”的规则，不调 margin 或过滤短接触。
- 不因场景修改造成版本/长度错配。若共享帧协议确需更改，更新两端并验证；优先避免协议扩张。

### 3. 记录与分析

记录实际场景名称与 ID；时间线标题和结果表包含场景列，不把不同场景的数据混写成一次 run 或当前成功率。每个 run 的 session、终止帧、停止确认和清理独立保存。

旧记录仍可分析，缺少新字段时显示已有历史名称或 UNKNOWN；原始记录及历史 INVALID 不改写。保持 S2-03 的提前准备停止发布器、及时 PASSIVE 与独立 cleanup 观察，不引入停止回退。

不将过去只适用于 obstacle_test1 的身份或“无碰撞”结论直接套到新环境。单次运行图表不表示跨场景性能已通过。
