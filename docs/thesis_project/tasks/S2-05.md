# S2-05：足端接触、足端撞击与终止碰撞分离

## 状态与目标

**COMPLETE（Director 有条件通过，2026-10-10）。**

用户冻结的运行规则：

1. 足端与障碍的轻微接触不计为终止碰撞，单独记录；
2. 足端满足水平冲击条件时记为“足端撞击”，单独记录，但仍不终止运动；
3. 机身、大腿、小腿等非足端与障碍接触继续作为终止碰撞；
4. 不隐藏任何接触，报告同时给出到达结果、非足端碰撞、足端接触和足端撞击。

本任务解决碰撞口径与记录问题，不调整 A 策略、RA 阈值、模型、控制速度或障碍布局，不开展正式性能实验，不实现 B/C/D，不训练、不实机、不提交 Git。

## 已核对依据与边界

- 当前 MuJoCo authority 把所有 group 3 机器人碰撞几何与障碍的接触统一记为 `robot_obstacle_collision`，supervisor 对任何此类事件立即终止，确实比用户要求严格。
- 原 ABS `testbed.py` 的碰撞口径包含指定机身/腿部接触，并用 `horizontal_foot_force > 2 * abs(vertical_foot_force) + 10 N` 识别足端横向撞击；还使用邻近障碍/速度条件过滤异常仿真接触。
- Go2 训练配置对 thigh/calf 接触和足端横向撞击设置惩罚，基础 episode termination 主要由 base 接触触发。因此“任何足端接触都失败”不是原训练/测试代码的规则。
- 原 ABS 测试脚本只检查 `feet_indices[:2]`；本任务依用户要求对四个足端统一执行同一条件。此处是明确的本项目规则，报告不得冒充逐字复刻论文。
- MuJoCo `mj_contactForce` 是接触坐标系中的接触力；Isaac Gym 保存的是刚体净接触力。二者不能直接当作完全相同的测量。实现必须说明坐标转换和聚合方法，并把 `10 N` 规则称为依据原 ABS 公式定义的 MuJoCo 对应口径。
- S2-04 稀疏 run 的 robot geom 42 经当前实际编译模型只读核对为 body 11 `RL_thigh` 上的碰撞 box，不是足端，所以该次 `COLLISION_TERMINATION` 仍属于非足端碰撞，不应重分类。

## 唯一术语和终止合同

### 足端范围

足端只指当前模型中具名 `FL`、`FR`、`RL`、`RR` 的四个足端碰撞球。大腿、小腿及其无名碰撞几何不属于足端。记录必须同时提供 geom ID、geom 名称；名称为空时补充所属 body ID/body 名称，不能仅凭画面猜测部位。

### 三类事件

| 事件 | 定义 | 是否终止 |
|---|---|---:|
| `foot_obstacle_contact` | 四个足端之一与已绑定障碍发生物理接触 | 否 |
| `foot_obstacle_impact` | 存在足端—障碍接触，且该足端本物理步的世界水平合力 `Fxy > 2*abs(Fz)+10 N` | 否 |
| `nonfoot_obstacle_collision` | 机器人任一非足端碰撞几何与已绑定障碍发生接触 | 是 |

轻微足端接触是没有满足撞击条件的 `foot_obstacle_contact`。等号边界不算撞击，即严格使用 `>`。

每个足端在同一物理步上的力应按具名足端刚体/碰撞体正确聚合：先通过 `mj_contactForce` 取得各接触力，按 contact frame 转换到世界坐标，并处理接触对中机器人 geom 位于 geom1/geom2 时的方向；需要说明是否将该足端同一步的所有外部接触（含地面）汇总。为接近原 ABS 的刚体净接触力语义，优先汇总该足端本步所有外部接触的世界力，但只有同一步确实存在足端—障碍接触时才判足端撞击。若技术核对证明另一种聚合更合理，报告必须给出直接依据，不能静默改变公式。

非有限力、无法确定方向、未知 geom/body 或记录覆盖不完整时，足端撞击结果为 UNKNOWN，不得默认轻微接触或无撞击。

- 保留 ground/self/other/unknown 分类及现有物理步覆盖规则。

- 至少累计并保存三类事件的次数、持续物理步/仿真时间、首末时刻、足端/机器人部位、障碍身份；足端撞击还保存触发周期的 `Fxy`、`abs(Fz)` 和阈值两侧数值。
- 运行终局只由 `nonfoot_obstacle_collision`、跌倒、到达、超时或安全中止触发；足端接触/撞击不得触发 PASSIVE。
- 单次结果必须分开显示：
  - `navigation_terminal_result`；
  - `nonfoot_collision_failure`；
  - `foot_contact_count/duration`；
  - `foot_impact_count`；
  - `arrived_with_foot_contact` 与 `arrived_with_foot_impact`。
- 为论文对比额外保留 `abs_reference_collision`：非足端终止碰撞或满足原公式的足端撞击即为 true。因为用户规定足端撞击不终止，某次 run 可以同时是 `ARRIVED` 和 `abs_reference_collision=true`。不得把它写成“无碰撞成功”。
- 时间线区分足端接触、足端撞击和非足端终止碰撞。旧 v3/v4 记录不回写；缺少力数据的历史足端事件只能标记 `foot_impact=UNKNOWN`。

先读取 AGENTS.md、CLAUDE.md、当前轻量文档、本任务、原 ABS 直接相关碰撞逻辑，以及当前 MuJoCo contact/authority、reader、supervisor 和分析器。连续完成后一次提交 Director 审阅。

1. 用生产判定函数覆盖四足名称、无名 thigh/calf 的 body 回退、严格边界（低于、等于、高于 `2|Fz|+10`）、geom1/geom2 方向、多个接触聚合、NaN/Inf、UNKNOWN 和非足端终止。
2. 使用实际 MuJoCo 模型的定向探针核对：足—地面不是足—障碍；足—障碍轻接触不触发终止；达到公式的足端撞击仍不触发终止；thigh/calf/base—障碍触发终止。若物理探针无法稳定制造指定力，生产力转换路径必须至少由真实 `mjContact`/`mj_contactForce` 样本核对，人工数值只验证公式，二者证据范围分开报告。
3. 严格验证 snapshot 跨语言版本/长度、reader、记录器、分析器和历史 v3/v4 兼容；运行必要增量构建与针对性检查，不跑无关整库测试。
4. 允许最多一次 `scene_ppt_sparse.xml`、当前 A、目标 `(7,0)` 的有界短诊断，运动上限 10 仿真秒、墙钟保护 120 秒。实际结果可以到达、非足端碰撞或其他合法终局；不得重跑直到出现足端事件，不制造接触、不关闭安全检查。
5. 如果出现足端事件，直接证明它被记录且没有导致终止；如果未出现，以探针证明运行规则，并明确实际运行未覆盖该事件。S2-03/S2-04 的停止、场景绑定、记录边界和清理不能回退。
