# S2-06：五个随机静态场景落地与单次功能诊断

## 状态与目标

**COMPLETE（Director 有条件通过，2026-10-10）。**

通过范围：五套固定布局接入、场景/射线/碰撞身份一致性核验、每场景一次有效 A 组诊断，以及原始周期、指标、时间线和收尾记录可复核。此结论不代表避障性能、成功率或切换效果通过。

把 `docs/thesis_project/designs/random_static_scenes/layouts.json` 中已经冻结的五套随机障碍布局转换为可选择、可记录、可分析的 MuJoCo 静态场景，并在相同 A 组配置下各完成一次短时功能诊断。

本任务回答“这五个布局能否被当前仿真链正确加载，以及机器人在单次运行中得到什么终局”。一次运行不用于计算成功率，不代表场景难度已经确定，也不属于正式实验。

## 冻结设计

- 场地范围：`x=-0.5..7.5 m`、`y=-3..3 m`；起点 `(0,0)`，目标 `(7,0)`。
- 五个布局、随机种子、障碍类型、尺寸、坐标和通道节点以 `layouts.json` 为唯一来源，不在运行结果出来后移动障碍或重新随机。
- 浅蓝通道总宽 `1.10 m`，只表示设计时存在几何通路。控制器不得读取通道节点或虚线路径；机器人仍只使用现有目标命令、状态观测和 11 条 ray2d 自主运动。
- 五个场景建议命名为 `scene_random_01.xml` 至 `scene_random_05.xml`，场景 ID 与文件名一一对应。

## 允许范围

- 编写可重复的布局到 MJCF/XML 转换工具，或直接生成五个确定 XML；
- 将五个场景接入现有 `--scene`、场景身份、射线、碰撞、记录和分析链；
- 对五个场景进行 MuJoCo 编译/加载及障碍集合一致性探针；
- 每个场景最多取得一次有效 A 组短诊断；基础设施失败或运动开始前的无效 run 修复后可重试，但必须保留原失败记录；
- 生成单次结果表和必要时间线。

## 禁止范围

- 不训练或修改 Agile、RA、Recovery 模型；
- 不修改 A 的阈值、切换语义、速度或到达半径来迎合结果；
- 不实现 B/C/D，不开展正式实验，不从单次结果计算成功率；
- 不把保留通道作为规划轨迹发送给机器人；
- 不因碰撞或超时重新随机同一场景；
- 不提交 Git。

## 实施与核验

### 1. 场景生成

1. 从 `layouts.json` 读取五套布局，生成对应 MJCF/XML；方箱和圆柱的平面尺寸、位置及高度保持一致。
2. 使用与现有场景兼容的地面、光照、机器人 include 和相机范围。
3. 为每个障碍生成稳定且唯一的名称，使碰撞结果能指出场景、障碍编号和机器人部位。
4. 保存生成来源、随机种子、布局文件和障碍数量；不得把 PNG 作为运行权威。

### 2. 生产链接入

五个场景必须在以下位置使用同一身份和同一障碍集合：

- `scripts/s1_run_diagnostic.py --scene`；
- MuJoCo runtime model；
- ray2d 障碍集合；
- collision authority；
- run context、结果表和时间线。

场景文件被修改后，现有身份/指纹机制必须能发现变化。

### 3. 运行前检查

对五个场景逐一完成：

- XML 编译/加载；
- 障碍数量、名称、类型和位置与 `layouts.json` 一致；
- ground 不进入障碍集合；
- ray writer 与 collision authority 指向同一障碍集合；
- 起点和目标邻域没有障碍；
- 设计通道未被任何障碍几何侵入。

### 4. 五次单次诊断

每个场景使用相同条件运行一次：

- A 组，`entry_threshold=-0.05`；
- 目标 `(7,0)`，到达半径 `0.5 m`；
- 仿真运动上限 `20 s`，墙钟保护 `120 s`；
- 相同部署模型、初始姿态和现有安全规则；
- 采集器先就绪，运行来源与场景身份必须有效。

合法终局包括 ARRIVED、非足端碰撞、跌倒、超时或安全中止。合法失败结果不得为了得到 ARRIVED 而重跑。若发生记录混流、场景身份错误、启动失败或无运动区间等基础设施问题，修正后允许取得该场景唯一一次有效诊断，原无效记录保留。

### 5. 每个场景记录

至少汇总：

- scene ID、随机种子、障碍数量和运行 ID；
- 终局、终点距离、起终点经过时间、有效连续间隔累计时间、有效连续片段路径长度及平均速度；
- Agile/Recovery 周期数、全部模式变化数与有效仿真时间变化数、RA 范围；
- 足端接触、足端撞击、非足端碰撞和跌倒；
- 策略频率、无效时钟帧和周期缺口；
- PASSIVE 确认、清理结果和适用限制。

输出一张五场景对照表。每个有效 run 保留现有时间线；不把五个单次结果汇总成成功率。

## 停止规则

- 若某个场景无法编译、场景身份不一致、ray/collision 障碍集合不一致，先停止运行并修正基础设施。
- 一旦五个场景各取得一个有效合法终局，立即停止，不增加重复次数。
- 不根据结果修改障碍位置；需要调整布局时先提交 Director 审阅，并把新布局作为新版本处理。

## 收尾要求

每次运行后关闭并核对本次 MuJoCo、controller、ROS launch、RViz、采集器、停止发布器和探针。只关闭来源明确属于本任务的进程。失败、中止和正常终局都必须执行收尾，并用通俗中文说明结果和环境状态。
