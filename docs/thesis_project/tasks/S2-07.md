# S2-07：到达后受控停止与稳定站立

## 状态与目标

**COMPLETE（Director 有条件通过）。** 通过范围：到达后停止运动、确认站稳并连续保持约 5 仿真秒；正常路径不自动趴下或卸力；运动指标排除收尾；先关闭 MuJoCo，再关闭 controller 等进程。通过依据及两次诊断证据见[执行报告](../evidence/S2-07/S2-07_EXECUTION_REPORT.md)。这不代表实机安全或完整避障性能已验证。

用户观察到 ARRIVED 后脚本请求 PASSIVE，机器人突然卸力。按用户最新决定，本轮目标收缩为：到达后冻结运动结果、停止导航并平滑减速、保持支撑并确认站稳、停留在固定站立。自动趴下卸力、新目标续跑和多目标任务留待以后，不再作为本任务验收要求。本轮只做仿真实现和验证；不授权实机测试。

**本版替代此前补证指令中要求继续修正下降 gate 和完成 DOWN/RELEASED 的内容。** 已有下降失败和无效启动记录原样保留，不重新解释成完成证据。

## 范围与原则

1. 正常 ARRIVED 以及传感、姿态、通信仍健康的受控超时采用受控停止和站立路径。
2. 人工急停、控制故障、跌倒、碰撞等异常不能盲目执行站立轨迹。保留现有急停优先级，本轮不声称现有直接 PASSIVE 已满足实机故障安全要求。
3. 不改变 A/B/C/D 运动期规则、模型、阈值、观测或研究指标。终局快照先封口，减速和站立属于独立收尾阶段，不计入到达时间、路径或切换统计。
4. 不直接把目标距离置零当作“保证停稳”；核对策略命令实际含义，保留有界减速与连续支撑过渡。关节目标不能从当前运动姿态突然跳到固定站立姿态。
5. 站立期间保持 controller、物理状态观测和必要支撑输出，禁止正常路径自动进入 FIXEDDOWN 或 PASSIVE。站立不是无限期或实机安全保证。

## 执行步骤

### 1. 读取与冻结收尾合同

读取当前轻量毕业设计文件、本任务及直接相关 controller FSM、FixedStand、默认姿态、停止发布器、supervisor、记录和分析代码。复用已实现的减速与站稳部分，确定站立完成后的保持行为，避免与 command 1/9、现有启动命令冲突。

在执行报告中先写清状态转移、各阶段期限、判据和异常退出行为。不得通过固定 sleep 或“命令已发送”宣称阶段完成。

### 2. 实现正常收尾

实现 `DECELERATING → STANDING → STANDING_HOLD` 或等价阶段：

- 禁止继续追逐目标，在仍有支撑控制的情况下平滑减速；
- 用有效姿态、速度和连续观察确认停稳；阈值与持续时间作为明确的仿真诊断参数记录，不宣称实机适用；
- 从实际关节状态平滑过渡到固定站立姿态，维持必要增益；
- 确认站稳后保持站立，不自动下降、卸力或重新进入 RL；
- 继续观测速度、姿态、关节跟踪、足端支撑、通信和物理源有效性；
- 进入站立有有界超时，站立观察也有明确上限，故障或人工急停可以抢占；禁止失败后自动站起或重新进入 RL。

核对已修正的 RL exit 正常过渡是否继续维持支撑，急停路径仍可抢占。现有 LOWERING/DOWN/RELEASED 代码不要求删除，但不得由本轮正常到达路径触发，也不继续扩展。

### 3. 有界站立观察与仿真关闭

- 为手动诊断提供明确的站立观察时长参数，默认 5 秒，限定为非负有限值并设置合理上限。计时使用仿真秒，墙钟保护独立；暂停不能导致无限等待。
- 已确认站稳后连续观察默认 5 仿真秒；必须有实际状态采样且始终满足站立保护，不能仅 sleep 5 秒认定稳定。
- 在窗口中展示/提示“已到达，保持站立”，使用户能观察到稳定状态；站立完成与环境清理分别报告。
- 有界诊断结束后，在控制器仍维持支撑时先停止本次 MuJoCo 物理环境并确认退出，再关闭 controller、ROS 和采集器；避免在仍推进的物理环境中先正常卸力。急停或异常兜底另行记录。
- 若无法完成预期关闭顺序，使用有界进程清理并如实记录，不能把兜底硬停称为正常站立完成。
- 此关闭方法仅用于仿真进程生命周期；实机退出、趴下与卸力仍留到 S9，不可移植为实机断控步骤。

### 4. 记录与分析

单独保存终局冻结时刻、减速与站立请求/确认、实际速度/姿态/关节状态、支撑与 kp/kd、站立观察起止时间及关闭顺序。分别报告 controller 模式确认、仿真侧物理状态和命令消费证据范围。收尾继续记录时不得把固定站立误解释为 Agile/Recovery，也不能把进程关闭日志误解释为正常卸力。
