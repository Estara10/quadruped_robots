## 冻结的功能规则

本轮 E=-0.05，H=0.30 秒。H 是功能诊断用候选，不是正式论文参数，也不是由旧 30 步换算得到的值。

| 当前模式 | 条件 | 下一模式及本周期动作 |
|---|---|---|
| Agile | 有效 RA >= E，且 C 的时钟有效 | Recovery；在此周期起算 H |
| Agile | 有效 RA < E | Agile |
| Recovery | 有效时钟显示 elapsed < H | Recovery，不因 RA 下降提前退出 |
| Recovery | elapsed >= H，且 RA < E | Agile，当周期退出并选择 Agile 动作 |
| Recovery | elapsed >= H，且 RA >= E | Recovery，不重启保持 |

- RA==E 时进入 Recovery，在 Recovery 中不满足退出条件；elapsed==H 按已到期处理。
- 从 Agile→Recovery 的有效模式决定周期保存 t_enter；elapsed=now-t_enter。保持限制模式驻留，不冒充命令实际生效后的保持。
- 使用当前 run 的 MuJoCo 仿真秒数，不按步数或墙钟计时；只在有效策略决策周期检查。
- C 时钟无效时，本周期不执行 RA 驱动转换，保持当前模式；无效 RA 及既有安全故障路径照常处理，不被 hold 掩盖。
- 同一 run 内时间回退/来源无效不重置或延长起点，不虚构到期；run 重置或 RL 新会话清除旧模式、计时和 Recovery 缓存。不得把旧 run 时钟当新 run。
- 仿真暂停时 H 不消耗；陈旧样本不能凭直觉当暂停。已有 DDS/安全 gate 优先，不为验证保持而关闭它们。
- Recovery 中再次满足进入条件不重新计时；重新从 Agile 进入才起算新一次 H。
- 碰撞、跌倒、到达、超时、人工停止和安全终止优先于后续切换；正常到达复用固定站立收尾。
