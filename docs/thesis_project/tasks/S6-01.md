## 运行前门槛与停止规则

1. 检查部署 controller 与 MuJoCo 的实际二进制/库加载路径确属本次构建；检查 overlay 是独立实体副本，不会写回源码或原安装配置。
2. 核对唯一 controller/writer、运行配置与模型来源、采集器先就绪、显示预检通过。每个 run 首帧及持续记录必须与预期组别/配置/来源一致。
3. 对 MuJoCo 面板的 A/B/C/D 分类、Agile/Recovery、C/D 保持状态和退出策略后的站立显示做离线核验；站立阶段不显示旧策略值。实际运行中尽量取得 LIVE 截图并关联组别及 run 身份；截图缺失不能触发额外运行。
4. 若来源混杂、配置不符、记录无效或其他基础设施故障使本批结果不可信，保留 INVALID 原始记录并停止尚未开始的后续组。不得关闭安全检查。
5. 碰撞、跌倒、超时、安全中止等是有效诊断结果，保留原样；不为获得 ARRIVED 或 Recovery 事件重跑。

## 指标核对要求

逐项定义指标、数据来源、覆盖要求及“可靠可用 / 部分可用 / 不可用”结论：终局与终点距离；运动起点至终局经过时间；有效连续时间；路径长度、平均速度和峰值速度；全部模式切换次数；0.5 秒窗口短反向切换；Recovery 单次驻留、累计时间及占比；风险进入到模式转换响应；足端接触、足端撞击、非足端碰撞；跌倒、安全中止和超时；无效时钟和策略周期缺口。

- 完整经过时间与有效连续时间分开；占比注明分子、分母及覆盖范围。
- 模式边沿统计不因时间无效而删除；时长、驻留和速度等时间指标只用有效连续覆盖。
- 缺失数据记 UNKNOWN/不完整，不插值。运动指标包含终止周期，排除站立和清理尾段。
- 控制接口命令写出不等于 MuJoCo 消费。无碰撞/未跌倒否定结论需要足够的相关运动窗口覆盖。
