## 已核对的源码语义

### ABS 部署参考：循环阶段，不是可靠的秒数合同

直接参考为 [`depth_obstacle_depth_goal_ros.py`](../../../ABS/deployment/src/abs_src/depth_obstacle_depth_goal_ros.py)。它是 Go1 SDK 部署示例，不是当前 Go2 ROS 2 控制器中的已执行逻辑；不得照搬到 Go2。

- `motiontime` 每轮加一；`dt=0.002` 虽有声明，但没有用于该阶段计时。循环每四轮调用一次 `rospy.Rate(50).sleep()`，其余轮次继续处理。因此阶段边界以循环计数定义，不能直接说成固定秒数。按循环结构估出的约 200 轮/秒只作名义估算，受实际处理时长影响。
- 计数 `<=500` 时先显示当前姿态并要求人工确认；只有 `motiontime>500` 才开始通过 `SetSend` 写电机命令。到策略控制标记 `real_control_start` 的计数 2000 之前，策略推理可能已经发生，但每轮动作会被启动阶段动作覆盖。
- `motiontime<1000`：动作来自实测关节偏差 `q-default`，乘以线性递减系数和4；命令目标是 `default+0.25*action`，开始时近似保持当前实测关节位置，再向默认目标过渡。
- `1000<=motiontime<1500`：写入相反方向、逐渐减小的关节偏差动作，目标最终回到默认目标。
- `1500<=motiontime<2000`：动作索引 `[1,4,7,10]` 加 `0.8`，`[2,5,8,11]` 加 `-1.2`；乘动作尺度 0.25 后，目标相对默认值分别偏移 `+0.2 rad`（大腿）及 `-0.3 rad`（小腿）。这是代码实际算式，不采用注释中与算式不一致的数值描述。
- `motiontime>=2000` 后，动作不再被这些启动分支覆盖，进入策略动作链。`last_action=action` 在每轮覆盖后更新，并回填 observation；因此策略开始时保留上一轮启动动作，不是零动作。
- 本示例电机 Kp/Kd 为 30/0.65；它采用 Go1 SDK 安全对象和特定部署脚本，不能证明用户的 Go2 当前运行具有相同阶段、时长或效果。

### 当前 Go2 控制器的 FIXEDSTAND→RL 交接

源码证据：[`BaseFixedStand.cpp`](../../../quadruped_ros2_control_humble/libraries/controller_common/src/FSM/BaseFixedStand.cpp)、[`StateFixedStand.cpp`](../../../quadruped_ros2_control_humble/controllers/rl_quadruped_controller/src/FSM/StateFixedStand.cpp)、[`StateRL.cpp`](../../../quadruped_ros2_control_humble/controllers/rl_quadruped_controller/src/FSM/StateRL.cpp)、[`RlQuadrupedController.h`](../../../quadruped_ros2_control_humble/controllers/rl_quadruped_controller/src/RlQuadrupedController.h)、Go2 ABS [`config.yaml`](../../../quadruped_ros2_control_humble/descriptions/unitree/go2_description/config/abs/config.yaml)。

- 固定站立以进入该状态时实测关节位置为起始目标，向 FR/FL/RR/RL 顺序的 `(hip=0, thigh=0.8, calf=-1.5)` 过渡。固定站立增益目标为 Kp=80、Kd=3；增益软启动为250个 controller update。
- 站立插值 `phase=tanh(percent)`；控制器实际日志记录 update rate 为200 Hz，`duration=frequency*1.2`，每次 update 增加 `1/duration`。命令3仅在 `percent>=1.5` 后允许。因此门槛处 `phase≈tanh(1.5)≈0.905`，不等于数学上的完整插值终点。S6-03 的 `[STAND-READY] percent=1.504167` 证明门槛通过，不证明身体姿态或插值目标完全到位；该任务另有物理稳定准入检查。
- 进入 RL 时，`StateRL::enter()` 把 `obs_.actions`、命令、接触及计时器重置为初始值，前一动作从零开始；`robot_command` 预装默认关节目标和模型增益。没有把 FIXEDSTAND 的最后一个动作作为 policy previous-action 输入，也没有对固定站立目标到首个策略目标做显式位置插值。
- Go2 Agile 配置给出动作尺度0.25、目标Kp=30/Kd=0.65、decimation=4、`soft_start_steps=250`。每个 controller update 的 `setCommand()` 将 Kp/Kd 乘以 `step/250`；实测 controller rate 为200 Hz，按源码应约1.25秒完成增益斜坡。YAML 注释所写“500 Hz/约0.5秒”与该运行的200 Hz日志不一致。运行周期帧没有逐周期保存实际 Kp/Kd，故斜坡的实际力矩效果尚未直接测得。
- `StateRL::run()` 每个200 Hz controller update 先增加同步 decimation 计数，达到4次才运行一次 `runModel()`；在此之前，预装的默认关节目标已经以低增益写出。因此 RL FSM 切入后、首个策略推理前最多有三个 controller update 使用默认目标和逐步上升的增益。首个策略计算从当前实测 `q/dq`、IMU姿态/角速度、足接触、目标命令、timer、射线等构造 observation；timer 按每个策略周期增加约0.02秒。`obs_.actions` 在入口被置零，故 cycle-0 observation 的前一动作是零。第一次策略动作计算后，目标成为 `default_dof_pos + 0.25 * clipped_action`（再经过关节范围裁剪），没有显式插值回 FIXEDSTAND 的最后目标。这是策略目标的直接生成规则，不等于该目标被 MuJoCo 确认消费。

### 证据分级

- **已证实：** 用户观察到现象持续存在且通常恢复；历史 S6-01 A 的已保存片段显示显著低高度、非足端地面接触计数、之后越过0.22 m并到达；新 S6-03 A/D 在高度最低点后开始上升时，0.30秒高度规则确认并终止。当前判据与训练 base-contact termination 在定义上不同。
- **源码支持的可能原因：** FIXEDSTAND 允许 command 3 时插值仍约剩9.5%；RL 入口将 previous action 清零、关节目标不显式与固定站立目标平滑衔接；策略期 Kp/Kd从极低比率启动并约1.25秒爬升。配合周期0已有向下速度，这些交接可解释短时下沉或支撑变化，但未证明是唯一原因或实际控制量效果。
- **尚未知：** S6-01/02旧轨迹的真实 RL 首周期及前段物理状态、接触的具体几何体和关节身份；S6-03全过程每周期实测 q/dq、实际增益和物理接触体；同一初始化条件下是否一定恢复；低高度持续时间与姿态/接触变化的因果关系；最终恢复是否可安全继续任务。

## 两种最小后续方案

### A. 四组共用的控制启动过渡

如有界观察证明当前交接造成可重复的目标/增益断层，可为 A/B/C/D 增加完全相同的 policy handoff：从 command3 时实测姿态和当前站立命令出发，将命令目标、控制增益按有界过渡接到相同策略输出；四组不得有组别专属门槛或时长。策略前一动作需按实际传入的策略语义明确初始化/回填，不能把 Go1 脚本的启动动作值直接填入 Go2 observation。所有接触、低高度、跌倒 episode 和启动阶段指标都保留。过渡时长应由仿真记录和 Director 审阅决定，本轮不指定或实现。

**影响：** 该方案会改变四组共同控制链和策略启动轨迹，适用于后续 A/B/C/D 必须统一的新代码；已有运行不能与之当作同代码数据直接合并。它不应改变任何 RA 阈值、保持时间、跌倒门槛或安全 veto。

### B. 原控制不变的有界启动恢复观察（推荐先做）

采用单次、非正式、仅用于判因的仿真诊断，不改模型、RA、控制目标、动作、增益斜坡或安全判据。观察时限从可核验的 controller `FIXEDSTAND→RL` 实际状态转换时刻起算，记录器同时绑定随后首个策略 `cycle-0`。只有在该转换时刻与时钟来源有效、可归属同一 session 时，才可启动计时；不能用较晚的首条 JSONL 帧替代交接时刻。交接时刻缺失、时钟无效或记录覆盖中断时，结果标 `UNKNOWN/INVALID`，不延后起点。最长 **1.0 MuJoCo 仿真秒**，不因 episode 重开、记录间断或恢复尝试重置计时。上限依据：历史已保存片段从最早可见低姿态恢复到0.22 m约需0.44–0.54 s（但起点不完整）；新 A/D 在0.46 s确认时已过最低点并开始上升。1.0 s 足以观察这段已知量级并留有限余量，同时不会无限容忍低姿态；它是诊断观察上限，不是新的跌倒阈值或安全承诺。

- 只允许临时延后“启动观察窗内、单独由低高度 `<0.22 m` 触发的任务终止”。生产 fall tracker 全程照常运行；候选、确认、开始/确认/结束时刻、全部足/非足端接触和恢复均原样累计记录，不清除或改写事件。姿态分支仍按原规则运行。
- 遇到已有 controller 安全 veto、数据/时钟/姿态来源无效、射线失效、非足端障碍碰撞、明显翻倒（含现有 `checkBodySafety()` 的75°即时 PASSIVE）、或其它既有硬停止条件，立即停止；不关闭或放宽任何安全检查。物理步/时钟覆盖中断时不得判恢复。
- 观察窗内只有当有效连续数据表明高度恢复到 `>=0.22 m`、姿态回到原判据范围、当前 fall episode 关闭，并连续0.30仿真秒保持有效正常状态，才记为“本次低高度事件已恢复”。若1.0秒到期仍未满足，立即按跌倒任务终止处理。确认过的启动 episode 即使恢复仍保留，并明确记为已恢复的启动安全事件；不得把该诊断称作无跌倒或安全成功。
- 诊断从真实 cycle-0 完整记录；启动期间的低高度、接触和事件都属于报告内容，不能延后任务起点或从安全统计中剔除。该机制仅限仿真判因，不适用于实机，也不得混入正式实验。

**推荐理由：** 当前最关键的未知是终止规则是否抢先结束了确能恢复的运行。B 保持策略控制链原样，只延长一次有上限的观察，最直接回答该问题；若它显示能恢复，之后再评估是否需要方案 A 的统一 handoff。B 不是已经授权的运行，本轮不启动。
