## 1. 生产增益合同

- 在RL进入时、写入任何RL增益之前，读取各具名关节command interface最后实际Kp/Kd为起点；不是yaml站立目标、实测关节角或被旧ratio处理后的RL值。确认前一状态退出不会先清零这些接口；若会清零，使用明确的交接保存，不猜值。
- 保存12组起点、策略目标及单位；起点必须有限且非负。启动状态或起点不符合准备合同则按既有异常/拒绝路径处理，不静默补80/3。
- 首次RL输出以保存的起点增益开始；之后线性过渡：Kp(t)=(1-alpha)*Kp_enter+alpha*Kp_policy，Kd同理；alpha限制在[0,1]。到期准确使用策略配置，不再同时乘近零soft-start ratio。
- 诊断过渡时长固定0.30秒，唯一工程字段建议abs.startup_gain_transition_s。它不是abs.switching.recovery_min_hold_s，不随A/B/C/D变化，不用于本轮研究参数扫描。
- 用有效controller运行周期period累计经过秒，首条交接命令elapsed=0，后续按实际周期增加；记录它是控制运行秒，不冒充MuJoCo仿真秒或Recovery H。不能靠固定200/500Hz步数假定时长。检查period非有限/负值，异常不得跳过安全或虚构过渡完成。仿真暂停/无控制update时不靠墙钟继续推进。
- 过渡仅在RL会话入口发生，Agile/Recovery切换不重启；重新进入RL重新读取实际起点。新时间状态不影响C/D仿真hold。
- A/B/C/D共享同一路径和时长，共用模型、观测、映射、动作缩放/裁剪及终局。
- 急停、safety veto、PASSIVE和状态退出优先；不得因过渡仍活动而重新写入非零增益。按实际调用顺序验证这一优先级。
- 本轮不改关节目标、前一动作初始化、timer、Kp/Kd最终值或策略动作；关节目标跳变继续如实记录。实机仍NO-GO，不部署或验证实机。
